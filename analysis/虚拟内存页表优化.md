# VM 页表改为匿名映射

2026-11-10，基于 `cbab9c2`。

## 实现

原来的 `PagedSegment` 用 `unordered_map<Word, unique_ptr<array<byte, 4096>>>`
模拟 64 MiB 稀疏段。每次访问都要查找页表，跨页还要循环。现在首次非空写入时建立
64 MiB 连续匿名映射，读写只做范围检查和 `memcpy`；未建立映射的段直接返回零。
`clear()` 和析构释放映射，移动操作转移唯一所有权。

- macOS/Linux 使用 `mmap(MAP_PRIVATE | MAP_ANONYMOUS)`，Windows 使用
  `VirtualAlloc(MEM_RESERVE | MEM_COMMIT)`。两个段合计最多占用 128 MiB
  虚拟地址空间，物理页按需提供；Windows 还会产生完整段的 commit charge。
- `zero()` 根据系统页大小处理首尾，完整页回收不会影响邻接堆块。
  Linux 优先使用 `MADV_DONTNEED`，失败时回退显式清零。
- macOS/Windows 先显式清零，完整页范围达到 256 KiB 才提示回收
  (`MADV_FREE` / `MEM_RESET`)。小块保留以减少系统调用和复用时缺页；
  此阈值是本次微基准下的策略，后续可以根据游戏实际分配轨迹调整。
  回收提示失败也不影响清零语义。整段清零直接释放映射。
- 范围校验改用减法，拒绝 `SIZE_MAX` 长度，避免加法溢出。
  `zero()` 的越界起点无操作，超长有效区间裁剪至段末。
- 映射失败抛出 `std::bad_alloc`，与旧实现分配页时的异常类型一致。

平台语义依据：[Linux mmap](https://man7.org/linux/man-pages/man2/mmap.2.html)、
[Linux madvise](https://man7.org/linux/man-pages/man2/madvise.2.html)、
[Apple MADV_FREE 定义](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/mman.h)、
[Windows VirtualAlloc](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualalloc)。
不能直接把 Darwin 的 `MADV_DONTNEED` 或 Windows 的 `MEM_RESET` 当作零填充操作。

## 微基准

本机 macOS arm64，系统页 16 KiB，Apple Clang，`-std=c++23 -O3 -DNDEBUG`，
无 LTO。同一份 `tools/bench_memory/main.cpp` 分别链接修改前和修改后的 VM 源码，
每项独立运行五次取最小耗时，包含首次分配/缺页和销毁成本。所有输出校验和一致。

| 工作负载 | 原页表 | 匿名映射 | 对比 |
| --- | ---: | ---: | --- |
| 200 万次 4 字节热点读写，16 KiB 范围 | 22.618 ms | 10.923 ms | 2.07 倍速度 |
| 200 万次 4 字节分散读写，64 MiB 范围 | 64.697 ms | 39.898 ms | 1.62 倍速度 |
| 4096 次 64 KiB 块读写，轮转 64 MiB | 12.866 ms | 14.068 ms | 耗时增加约 9% |
| 4096 次 64 KiB 写入/清零/读取零值 | 7.859 ms | 8.065 ms | 耗时增加约 3% |

最初每次完整页清零都发送回收提示，最后一项约 18 ms；小块复用策略消除了大部分退化。
直接映射主要改善 VM 小值访问，大块冷访问没有普遍加速保证。由于系统页为 16 KiB，
极稀疏写入的物理内存粒度也可能大于旧的 4 KiB 软件页。
这些数字不是实际游戏整体提速或帧率测量；Linux/Windows 分支尚未实机验证。

当前版本基准复现：

```sh
cmake -S . -B /tmp/openbgi-memory-release -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DOPENBGI_BUILD_RUNTIME=OFF -DOPENBGI_BUILD_TESTS=OFF
cmake --build /tmp/openbgi-memory-release --target obgi_bench_memory -j 8
/tmp/openbgi-memory-release/src/obgi_bench_memory
```

比较旧版时，把同一份基准源码编译链接到修改前的 `obgi_vm`；不要使用两份不同的
基准程序或用未开启优化的默认构建比较。

## 验证

- 完整单元测试：107 个用例、1788 条断言通过。
- 新增 3 个段内存测试：未写区域读零、段尾/溢出边界、移动与覆盖旧映射、清空后复用、
  4 KiB/16 KiB 跨界清零、大小范围的邻接字节保护、回收后重写、300 轮固定种子随机模型比对。
- 独立 Debug ASan/UBSan 构建，核心单元测试通过。
- GPU 和宿主测试通过；未执行依赖真实游戏目录的 game 测试。
- Release 基准构建目标独立于 SDL/GPU 依赖，可单独构建。
