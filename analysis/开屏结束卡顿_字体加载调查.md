# 开屏结束后卡顿：字体加载调查

日期：2026-11-08。状态：已定位主要耗时，尚未优化。

在本机使用 Debug 构建和《Amairo Chocolate 2》数据、无窗口运行时，开屏结束后的一次 `92:9C` 文字绘制约耗时 4.2 秒，几乎全部发生在首次打开字体，而非游戏数据包读取。临时计时代码已撤回；该结果不代表所有机器或 Release 构建的耗时。

| 字体 | 文件大小 | 首次打开耗时 |
| --- | ---: | ---: |
| 微软雅黑 msyh.ttc | 约 19 MB | 1.1 秒 |
| 宋体 simsun.ttc | 约 17 MB | 1.0 秒 |
| 微软正黑体 msjh.ttc | 约 20 MB | 1.2 秒 |
| 游ゴシック yugothr.ttc | 约 13 MB | 0.8 秒 |

`src/text/font.cpp` 的 `FontLibrary::open` 同步打开主字体和所有可用后备字体；`open_path` 使用流迭代器逐字节读入字体文件。此次测量中字体文件名查找仅占几十毫秒。图片同步加载也有开销，但不是这次数秒停顿的主要来源。

建议先按需打开后备字体，只在主字体缺字时尝试；同时改为预分配缓冲区并批量读取文件。需比较 Debug/Release 和交互窗口下开屏结束到标题画面可操作的耗时，并验证中文、日文及缺字回退、字体对象生命周期和缓存。若仍有明显停顿，再评估开屏期间后台预加载，并处理线程安全和退出生命周期。
