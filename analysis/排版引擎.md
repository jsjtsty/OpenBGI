# 排版引擎 FUN_0043ba90 的动态验证（Unicorn + GDI 打桩）

`92:9C` 的实际实现 `FUN_0043ba90`（1599 行）此前只有静态阅读（见 `文字绘制.md`）。本文用 `scripts\verify_layout.py` 把**原引擎的排版函数、字体对象构造函数、字形获取函数原样跑在 Unicorn 里**，只替换 Win32 导入函数，得到可对照的结果。

## 1. 方法与打桩边界

- `scripts\winstub.py`：解析 exe 的导入表，把每个 IAT 槽指向一个桩地址，代码钩子按 stdcall 分发到 Python 实现。未实现的导入会报名字，因此打桩范围是**用到才补**。
- `scripts\verify_layout.py` 实现的 Win32 桩：`MultiByteToWideChar/WideCharToMultiByte`（按 Python 编码）、`CreateFontW/CreateCompatibleDC/CreateDIBSection/SelectObject/GetObjectA/DeleteObject/DeleteDC/GetDC/ReleaseDC/EnumFontFamiliesExW`、`GetOutlineTextMetricsW/GetTextMetricsA/GetGlyphOutlineW/GetCharABCWidthsFloatW/GetTextExtentPoint32W/TextOutW`。字形形状是合成的（CJK 全宽、ASCII 半宽的矩形墨迹），**不是真实字体**。
- `emu.py` 新增：FS 基址指向零填充的 TIB（SEH 序言要读 `fs:[0]`）。`DAT_00597288`（`std::list` 哨兵，CRT 静态初始化没跑）手工初始化。
- **跑的是真代码**：`FUN_00432cc0/004333c0/00433690`（CFontDx 构造）、`FUN_004345c0/00433ba0`（字形缓存与灰度转 alpha）、`FUN_00439040/0040a090`（着色）、`FUN_0043ba90`（排版）、`FUN_0043a4a0/0043a500`（配置设置函数）。
- **替换的是**：GDI 本身（真实字体光栅化、真实字距）。因此下文的"已验证"针对**引擎逻辑**，不针对 Windows 字体渲染结果。

运行：

```
analysis\.venv\Scripts\python.exe scripts\verify_layout.py -g          # GGO 灰度路径
analysis\.venv\Scripts\python.exe scripts\verify_layout.py -r 1200 150 # 随机文本：真引擎 vs Python 参考模型；150=最小宽度
```

## 2. 调用约定（已验证可直接调用）

`FUN_0043ba90`：`__fastcall`，`ecx` = 节点链表头（100 字节清零），`edx` = 行数输出指针；栈参数按顺序：文本（UTF-8 或 CP932，自动判别）、ruby 开关、ruby 表指针、光标 `int[2]`（x,y，原地更新）、矩形 `int[]`（`[0]`=左界，`[2]`=右界，折行用）、行间附加像素、字体 ID、竖排、**禁则开关**、文字颜色、效果 `int[5]`（模式, P1, P2…）。字体由 `FUN_0040a030(DAT_0053605c, 描述符, 字体ID)` 取得：`DAT_0053605c → M1`，`M1+4 → M2`，`M2+0xf8` 为条目链（`+0` 字体 ID，`+4` 起 29 个 dword 描述符，`+0x78` 下一个）。描述符：`+0x00` 字体名（C 字符串）、`+0x60` 字号、`+0x64` 宽度百分比、`+0x68` 粗体、`+0x6c` 斜体、`+0x70` CFontDx 对象。输出节点（100 字节，链表 `+0x60`）：`+4` 逐字显示时间偏移、`+0x10/0x14` 左上 (x,y)、`+0x20` 字号。

## 3. 已验证（与原引擎对照）

1. **CFontDx 构造 + 字形获取在桩 GDI 下可运行**。默认全局值（exe 的 .data 初值）：`DAT_0052eb88=1`（TextOut 超采样路径）、`DAT_0052eb8c=1`（4×）、`DAT_0052eb80=4`、`DAT_0052eb90=4`。字形单元 = `字号×宽度%×2/100` 宽、`字号×3/2` 高（字号 24 → 48×36）。
2. **超采样转 alpha**：`alpha = 采样命中数×255 >> 4`（4×4 块）。对 3 个码点逐像素对照，0 处不同。
3. **GGO 灰度路径**（启动自检 `FUN_004761a0` 失败时回退到 `FUN_00433200`，使 `DAT_0052eb88=0`）：`alpha = v×255 >> {2,4,6}`，分别对应 `DAT_0052eb8c = 0/1/2`（GRAY2/4/8）。3 个模式 × 3 个码点逐像素对照，0 处不同。
4. **字宽与光标步进**（水平排版）：
   - 全宽字（非 ASCII 且不在 U+FF61–FF9F）宽 `字号×百分比/100`（整除），半宽字（ASCII、半角假名）为其 `/2`（整除）。**字宽完全不取自 GDI 的 ABC 宽度**，只取自这两类；排版因此与操作系统字体无关，可直接移植。
   - 每字光标前进 = 字宽 + `(int)字体对象+0x48 的浮点`（默认字体为 0）+ `DAT_005378a4`（字间距，由 `91:98` 第 3 参数设置；实测 3 → 24 变 27，ASCII 12 变 15）。
5. **折行**（折行判定量 `L = 矩形右界 − 边距 + 1`，字放入条件 `光标x + 字宽 ≤ L`）：
   - 禁则开关为 0：`边距 = 0`，逐字贪心折行。
   - 禁则开关非 0：`边距 = DAT_0052ec04 × 字号`。**与 `DAT_005378a8`（悬挂标点开关）无关**（实测 `91:98` 的悬挂参数 0/1 结果相同；`DAT_0052ec04` 取 0/1/2 时 4/3/2 字一行）。
6. **禁则规则**（已用随机文本对照，见 §5）：
   - 以每个字为"基字"，向后取一串"行首禁止字符"（表 `0x5146e0`，71 字）。其中**简表** `0x514790`（63 字：标点、右括号、`ー～…`、小假名，不含 `: ; ‐ を ヲ`）里的字可以**悬挂**进右边距；表里其余字（`: ; ‐ を ヲ`）必须留在行内。
   - 组 A = 基字 + 串中到**最后一个非简表字**为止的部分（必须同行）；组 B = 其后的简表字（可悬挂）。
   - 基字若在"行尾禁止"开括号表 `0x514770`（14 字）且后面没有行首禁止串，则度量时把**下一个字**也算进组 A（避免开括号单独留在行尾）。
   - 折行判定：`x + wA > L` 时折行，但基字本身属简表且 `x + wA ≤ 右界+1` 时允许悬挂；否则当 `wB > 0` 且 `右界 + 1 < x + wA + wB` 时折行。
   - 组被接受后，串中的字逐个放置（逐字判定：超过 L 的简表字只要不超过 `右界+1` 就悬挂，非简表字不允许）。折到新行后，若组 A 在新行放得下，则**丢弃分组**，后面的字重新当作基字各自带自己的串（所以一长串标点会分多行）。
   - 拉丁单词（禁则开关非 0）按单词整体折行；超过一整行的单词在行内按字断开（`FUN_0043f440`，行为抽查一致，未做随机对照）。
7. **配置写入函数**（`FUN_0043a4a0`、`FUN_0043a500`）：可原样调用，结果如上。
8. `<t N>`：`+4` 是**逐字显示的时间偏移**，不是水平偏移。默认第 k 字为 `k×DAT_0052ebfc`（`91:98` 第 1 参数，.data 初值 25；实测改 40 则 0/40/80…）。`<t N>` 把**后续**偏移置为绝对值 `N×DAT_0052ebfc`，之后继续每字累加（`あいう<t 2>abc` → 0,40,80,80,120,160）。`文字绘制.md` 里"水平偏移"一说有误。
9. `<cr>`：光标 x 回到行首，不产生节点；`<ev N>`：不产生字形节点（登记事件）。`<c RRGGBB>` / `<b>` / `<2x>` 不产生节点，`<fs N>` 会让后续节点字号变化（实测 `<fs 12>` 的字宽为 12）。
10. 悬挂缩进（`FUN_0043f410`，表 `0x5146cc` = `「　（『"`）：**禁则开关非 0** 且文本以表中字开头时，续行缩进该字的字宽；开关为 0 时不缩进。前缀控制字符 `\x04`–`\x08` 在禁则开关非 0 时同理（首行光标右移一个缩进宽，续行同宽）。
11. `DAT_00538208`（`FUN_0043a500` 键 `0x80000009`）= "变高行"模式：行内混有更大字号时，行高 = 基础行距 + (该行最大字号 − 基础字号)，同行较小的字按底端对齐下移（实测 `あい<fs 48>う</fs>え` 在字号 24 基础上：小字 y=24，大字 y=0，下一行 y=54）。默认 0，此时 `FUN_0043e590` 恒返回 0，行高就是传入的行间像素。

## 4. 修正此前文档的错误

- **前缀控制字符 `\x05/\x06/\x07`**：`DAT_00538204 == 0` 时用**全角**字符（U+3000 / U+FF08 / U+201C），非 0 才用 ASCII。`文字绘制.md` 原写反。
- **`<t N>`** 是时间偏移（见上）。
- 折行边距**不依赖** `DAT_005378a8`（见上）。`DAT_005378a8` 只影响缩进初始化。

## 5. 与参考模型的随机对照

`ref_layout()`（Python，约 30 行）实现 §3 第 5、6 条。随机文本由常用字、行首禁止字、开括号拼成（不含 ASCII 以避开单词逻辑），禁则开关随机 0/1。

| 宽度范围 | 用例数 | 不一致 |
|---|---|---|
| 150–400 | 869 | 0 |
| 80–330 | 869 | 1 |

唯一不一致的用例出现在**一行只放得下约 2.5 字**的极窄宽度（组 A 比一整行还宽）。此时引擎不接受分组，之后逐字行为与模型不同。游戏对白宽度远大于此，**记为已知角落，未解**。

### 5.1 拉丁单词折行（`scripts\verify_layout_words.py`，按节点坐标对照）

模型：从非"待放"状态的 ASCII 字符起，取最长的可见 ASCII 串（0x21–0x7e，不含空格和 `<`），再从末尾剥掉 `! " ) , . ? ] }`（至少留 1 字符），整串当作一个单位：`x + 单词宽 > L` 就折行；接受后串内字符逐个放置。**行尾放不下的 ASCII 空格直接吞掉**（不产生节点、不折行）。折到新行后若单词仍比一行宽，则单词在行内按字断开。

- 禁则开关 0：吞空格规则**不适用**（空格正常占位或折行），单词整体折行仍适用。
- 禁则开关 1：单词之后紧跟的"行首禁止"串（含刚被剥掉的 `! " ) , . ? ] }`）与 §3.6 同样处理——组 A 含单词和串里最后一个非简表字之前的部分，其余简表字可悬挂；只有"单字符的单词"（如孤立的 `,`）才享受悬挂豁免，`"hi"` 这类以标点开头的多字符词整体按单词折行；吞掉的空格实际是**折到下一行并丢弃**（行首空格不画）。
- 文本以 `"`（ASCII 双引号）、`「`、`　`、`（`、`『` 开头且禁则开关非 0 时，续行自动缩进该字的字宽（表 `0x5146cc`）；模型里必须加上这一条。
- 以上规则写进 `verify_layout_words.py`，**按节点坐标对照 1500 例随机文本（单词表含 `world,` `test.` `"hi"` `(a)` `end!?` `ok)`，宽度 150–400，禁则 0/1 各半），0 处不同。**

### 5.3 文字效果与竖排标志（探测结果，原函数输出）

- 效果结构 `int[5]` = {模式, P1, P2, 颜色, 不透明度}。`a = max(1, P1×字号/100)`，`b = max(1, P2×字号/100)`。
- 模式 1（投影）、2（描边）：折行判定要把 `a` 加到字宽上（`字号 24, P1=P2=40%` → `a=9`，宽 100 的行从 4 字变 3 字）；光标步进**不含**效果宽度。
- 模式 2：节点 y 下移 `b`，**仅当 `DAT_005381bc≠0`**（游戏里 `91:9A` 设为 1；设 0 则不下移）；x 不移。光标 y 不受影响。
- 节点 `+0x18/+0x1c`：`DAT_005381f8≠0` 时 = 位置 + (a,b)（模式 0 时 a=b=1），否则 = 位置。
- `param_10`（`92:9C` 第 13 参数，“竖排标志”）非 0 时，字仍从左到右、`
` 仍向下换行，**字宽改由字形墨迹框计算**。原因（读 `FUN_0043b310`/`FUN_0043e640` 得出）：该标志非 0 时 `FUN_0043e640`（字间距 `DAT_005378a4` + 字体附加量）直接返回 0，`FUN_0043b310` 走另一支：用字形的 A/B/C 浮点值经 `FUN_0040a8e0`（按 `DAT_0052eb78` 的 16.16 缩放裁剪）和 `FUN_0043a2e0` 取整得到步进与起点偏移。因此步进依赖**真实字体的 ABC 与墨迹框**——fake 字体下得到的 `字宽+3`、12→7、32→21 等数字只是 fake 墨迹框的产物（字号 24 时首字 27 而后字 15 也不规则），**不能当作规律**。`DAT_0052eb78` 由 `91:99` 设为 `(v+0xffff)/v`，为 0 时 `FUN_00408bc0` 返回 −1。游戏是否实际传非 0 未统计。

### 5.2 ruby（已用 Unicorn 对照，`scripts/verify_ruby.py`、`verify_ruby_model.py`）

**登记与匹配**：
- `ruby 开关≠0`（`92:9C` 第 6 参数）时才处理 ruby，正文所有节点整体右移 `DAT_00537898`（`91:98` a5，游戏里 16）、下移 `DAT_0052ebe8×字号/100`（33%×24 → 7）。开关为 0 时 ruby 标签无效。
- 登记表在 `FUN_0043ba90` 的 `ruby 表` 参数（结构 +0x24 为条目链表头）。条目 40 字节：`+0` 基文串，`+4` 基文字节数，`+8` 基文字数，`+0xc` 注音串，`+0x14` 注音字符码数组，`+0x18` 注音字数，`+0x1c` 一次性标志，`+0x20` 保留，`+0x24` 下一条。
- 三种来源：`<r注音>基文</r>`（游戏实际用法，`<r` 后紧跟注音，空格会被跳过），`<ruby 基文,注音>`（一次性条目），以及词典串（`FUN_0043adb0` 解析 `基文\注音
`，即 `\` 分隔、换行结束，条目不是一次性的，游戏里 `92:9C` 第 7 参数）。
- 词典匹配（`FUN_0043abe0`）：从当前位置起，按**登记顺序**取第一条“基文是剩余文本前缀、且未被用掉”的条目；一次性条目用过一次就失效（所以 `<ruby 漢字,かんじ>漢字あ漢字` 只有第一个“漢字”带注音）。先登记的短条目会抢在后登记的长条目前面（`<ruby 漢,かん><ruby 漢字,かんじ>漢字` 只给“漢”注音）。
- 排版函数只把匹配到的基文串记在首个基文节点 `+0x54`，基文总宽记在 `+0x58`；注音节点由 `FUN_0043b030` 在排版之后调用 `FUN_0043e750` 生成（对每个带 `+0x54` 的节点调 `FUN_0043e910`）。

**注音节点布局**（`FUN_0043e910`，注音字体字号 `max(4, DAT_0052ebe8×字号/100)`，`DAT_00537894≥1` 时取该值）。记基文节点 x 为 X（含效果偏移），基文宽 `baseW`，基文字数 `bc`，注音字数 `n`，注音第 i 个字的字宽（浮点）为 `gw`、含间距的步进为 `adv`：
- **注音比基文宽**（`baseW < Σadv`）：从 `X + ((baseW − Σadv) >> 1)` 起，**逐字紧挨**排，x_i = 起点 + Σ_{j<i} adv_j。
- **否则**：均分，`step = (baseW+1)/n`（浮点），x_i = round(X + (step − gw)/2 + i×step)（四舍五入）。
- y = 基文节点 y2 − 注音字号 + `DAT_00538200`（效果模式 2 再减 b）；node +0x14 为 0，`+0x5c` = 2 标记为注音节点；`+0xc` = `DAT_0052ec08`。
- 逐字显示时间（节点 +4）：`L = (bc × DAT_0052ebfc) / n`（整数除），第 i 个注音字的时间 = 基文节点时间 + (L>>1) + i×L，即注音字均匀铺在基文所占的显示时间内。
- 注音字形 bitmap 的尺寸是字宽 + 效果占用 × 注音行高；效果模式 1/2 的投影/描边与正文同一套；内容来自注音字号的字形渲染（未单独核对）。

**对照结果**：fake 字体下（注音字宽 7、含间距步进 8）注音字数 1–8、基文字数 1–7 共 56 组，x 与时间偏移与上述模型**全部一致**（`verify_ruby_model.py`）。游戏中 124 处 `<r>` 的（注音字数, 基文字数）分布：(3,2)17、(2,2)17、(4,2)14、(3,1)14、(2,1)13、(3,3)13、(4,4)8、(1,1)5，其余少量，最大 (7,7)，都在已验证范围内。真实字体的 ABC 宽度会改变 `gw`/`adv`，公式本身不变。

**坑**：连续多次调用 `FUN_0043e750` 时，`FUN_00434e10` 会把新建的注音字体挂进字体管理器的链表，harness 重置堆会让它悬空；`verify_ruby.py` 每次先断开原链表尾。字体管理器还需要 `M2+0x78=0x100`（默认超采样倍数）与足够大的对象（别名表在 +0x170），否则注音字体创建失败（返回 `0x80000001`）。
