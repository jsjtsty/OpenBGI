# 后台资源解码实施与验证（2026-11-09）

## 实施范围

交互式会话默认启用后台资源解码。图片 `90:10`、音频 `A0:11/12/20/21` 的 DSC 解压、格式解码、像素转换以及 intro/loop PCM 拼接在工作线程执行。资源解析、缓存管理、GPU 上传和 Mixer 安装仍由 VM 主线程负责；工作线程只接收拥有生命周期的输入和纯解码函数。

普通确定性无头回归保留同步行为；`--async-resources --pace-headless` 可在固定虚拟时钟与输入序列下观察真实后台任务。后者按每帧 16 ms 实时节奏运行，避免无节奏的虚拟帧在工作线程获得 CPU 前就跳过输入时间。

缓存命中立即完成；未命中时使用零返回值 Poll 等待，挂起请求线程并保持依赖顺序。队列拥堵只等待，不回退到主线程解码。独占 VM 线程仍遵守原有独占规则。

## 队列、缓存与生命周期

- 默认两个工作线程，最多八个已准入任务；按输入大小加估计工作空间控制 256 MiB 准入预算，单个超大资源可独占运行。这是估算值，**不是进程内存硬上限**。等待准入的请求仍持有输入；完成结果、活动使用者和缓存的内存另计。
- 解码完成即释放准入额度，避免完成结果阻塞其他线程或 intro/loop 后续依赖的解码。图片和 PCM LRU 分别保留 128 MiB、64 MiB 限制。
- 同一归档成员的并发请求共享一次解码；取消其中一个使用者不影响其他使用者。缓存 clear 使用代次，旧任务不会重新填入清空后的缓存。
- loose 覆盖文件不缓存、不合并；每次重新读取。读取在后台通过文件句柄复制到拥有所有权的缓冲区，避免异步 mmap 遇到文件截断产生 SIGBUS。归档数据继续复用已有 mmap 所有权。
- 图片槽与声道使用加载 ticket。新加载、内容替换、释放、停止等使旧结果失效；后台结果不能覆盖新状态。等待被销毁时释放消费者，排队取消任务跳过解码，运行中的任务完成后丢弃结果。
- 队列关闭丢弃未执行任务并完成其错误 future，仅等待已经运行的解码。当前不能强行中断正在执行的 codec。析构顺序确保工作线程不访问已经销毁的会话对象。
- 解码错误保留原图片，错误包含资源名、VM 线程和 opcode；失败请求不会永久等待。
