# 运行时核心重构实施记录

日期：2026-11-03。本次直接在已有未提交工作的基础上修改，保留了原有输入、面板、图像等工作，没有重置工作区。

## 已替换的结构

### 唯一运行会话

新增 `runtime/EngineSession`，拥有渲染器、显示、字体、资源、音频、消息、序列、影片、绑定和 VM。按明确顺序销毁：先取消 VM 等待，再释放服务/后台任务，最后释放字体与设备。

`obgi_run` 不再自行装配这些对象，也不再拥有另一套窗口输入逻辑。交互模式使用单调真实时间；离线模式使用虚拟时间，解码任务同步执行，日历查询使用固定 UTC 起点。音频设备不可用或离线运行时，仍按准确采样数量推进播放、循环和淡变，保留不足一个采样的时间余量。

默认持久目录从共享临时目录改为用户数据目录中的游戏专属目录。`restart()` 构建新的完整会话后替换旧会话，旧会话等待和任务不会写回新状态。调用者持有的内部引用在 restart 后需要重新获取。

### 调度、等待与生命周期

- RC 2 重新进入当前线程状态检查；无等待对象时可在同轮继续执行。
- 缺失的线程切换目标结束本轮调度。
- 支持独占线程；线程退出后及时解除独占并回收程序、栈和等待对象。
- `80:5C` 按毫秒计时，结果由等待完成交付。超时/通知返回 0，输入结束返回 1，输入优先级在完成、取消和销毁时对称释放。
- `SubopDef` 区分总返回数与允许延迟交付的返回数。解释器验证即时变化，调度器验证完成返回数和栈位置，再统一写回。
- 文字、运动、序列和影片绑定不再手写表达式栈。新增完成 trace；取消使用统一 cleanup。
- 重复 opcode 注册直接报错，清理了五处装配覆盖。注册查询使用按 opcode 高字节分配的索引页，保留有序描述表用于诊断。

语义核对参考了本项目 `analysis/线程调度.md` 及 `D:/CodeSpace/openbgi` 中的 `vm/sched.c`、`vm/ops_sys.c`、`wait/wait_sys.c`。这里实现的是 C++ 运行时协议，没有引入该项目的完整 C 运行时。

### 领域状态与后台工作

- `InputState` 与优先级消费逻辑移至 `services/input`，VM 通过 `WaitInput` 端口访问输入。
- `SceneState` 独立拥有精灵、创建顺序和主从关系，可在无 GPU 的情况下复制与测试。Display 保留兼容 API 并委托场景操作。
- `MessageService` 显式保存渐显进度和截止时间；按经过的毫秒推进，不再通过每次 poll 加一帧计时。稀疏更新不再推迟自动结束时间。
- `SequenceService` 拥有序列、解码位置与操作。使用一个工作线程取代逐调用 `std::async`，任务仅持有输入数据。future 销毁不再等待一条独立线程。
- 图槽增加内部 generation。异步完成会检查图槽是否仍是发起时的对象；同尺寸重新创建也无法被旧结果覆盖。脚本可见图槽编号保持原样。

### 影片、声音与字体

`MoviePlayer` 按 tick 逐步推进，不自行处理事件或运行 VM 主循环。影片和普通场景由同一会话呈现，使用实际逻辑画布尺寸。持续更新复用视频纹理；`90:F2/F3` 由影片服务处理实际播放状态和音量。普通场景显示被关闭时，影片仍可正常呈现。

独立查看工具的阻塞式 `play_movie` 现在只是 MoviePlayer 的薄适配器，旧的播放器实现已删除。

混音和音频供给使用固定大小缓冲，回调不再为累加数组或 scratch 扩容；混音锁按固定小块持有。旧 PCM 在控制调用释放锁后销毁。这里仍使用互斥锁，不宣称已经实现完全无锁音频或流式声音解码。

字体查找有缓存，主字体/字号缓存有数量上限，fallback 使用独立叶子 face，避免互相 fallback 的所有权环和递归查询。字体对象持有 FreeType 生命周期，可安全晚于 FontLibrary 销毁。修正了无条件用中文 fallback 覆盖指定字体的问题。`B0:C3` 真正注册内存字体，不再只判断资源存在就返回成功。

### 资源和构建

归档存储下移至 `resources/`。程序加载器与媒体共用归档映射；程序使用精确归档查找，媒体按显式搜索目录、游戏裸文件和归档规则解析。`80:37` 的搜索目录有实际消费者；明确指定的损坏归档会返回错误。

新增 `OPENBGI_BUILD_RUNTIME=OFF` 和 `windows-core` preset。核心构建无需 SDL、FFmpeg、FreeType 和着色器工具链。公共 preset 移除本机代理，默认游戏目录不再写死。

## 启动淡入修复

随后根据启动页淡入异常逐帧排查，确认 `90:05` 被误实现为仅校验优先级范围。该指令实际是 `(目标图槽, 最高优先级)` 的场景截图，包含指定优先级的对象。启动脚本用它生成淡入的目标图片；旧实现没有生成图片，又将脚本图槽 3793/3794 猜测成空白图和实时屏幕别名，导致淡入阶段混合黑图，到结束时直接显示品牌标志。

修复将 `90:04/05` 截图交给 graphics 绑定和独立 GPU 目标，恢复正常图槽语义，截图不会覆盖显示中的 back buffer。另固定了背景双层的先后顺序，使创建顺序不能让下层盖住淡入的上层。

回归覆盖截图优先级的包含边界、忽略实时绘制下限、排除上层黑色滤镜、保留显示帧，以及真实启动品牌标志淡入的初始/中间/结束像素亮度。修复前虚拟 3520 ms 的截图全黑，修复后同一时刻为约半亮品牌标志。日志和截图在 `build/windows/fade-*`。

修复后完整 Debug 套件 99 个用例通过；另外运行 3000 轮到标题菜单，无脚本错误，截图 `build/windows/fade-title-fixed.png` 已核对。Debug 的 `obgi_run.exe` 已重新构建。

## 仍需继续验证和迁移的范围

这次完成了核心运行模型的替换，不等于全部 BGI 行为已重写和验证：

- 完整禁则、注音、竖排及字体度量兼容仍需独立实现与原版对照。
- 部分窗口、面板、粒子和特效逻辑仍在 bindings；Display 还包含背景/地图等兼容状态和 CPU/GPU 缓存。
- 目前没有完整会话检查点格式，不能把显式消息进度或 SceneState 副本当作任意时刻可恢复的整局存档。
- 声音仍整段解码，部分图形效果仍需要同步 GPU 回读；本次消除了若干明确的分配和线程问题，但没有给出整机性能提升百分比。
- 部分历史处理器仍只实现部分行为，注册数量不代表完整语义覆盖。其他游戏、引擎版本、Linux/macOS、完整通关和所有存读档路径尚未验证。

后续迁移应沿用现在的边界，继续把窗口/排版及可变图像状态抽成服务，并补齐检查点和行为证据，避免重新让 opcode 闭包拥有业务状态或直接访问线程栈。
