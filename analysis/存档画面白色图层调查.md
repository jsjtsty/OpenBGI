# 存档画面白色图层调查

日期：2026-11-08。使用用户最近的存档副本复现；原始存档未修改。画面为咖啡店背景与紫发角色，初次读档后右上角出现白色矩形。

## 已确认

- 引擎截图和各图像槽的像素表明，背景图片完整；白色来自 `data02xxx.arc/white`，由槽 33、34 对应的投影对象叠加。人物位于这些图层之上。
- 首次读档时，其中一个白色对象的位置为 `(0, -850)`，定位原点为 `(0, 0)`；重读后原点变为 `(660, 190)`，白色区域随之变成上下横条。白色素材实际尺寸为 1320×760。
- 原版的位图管理器初始化（`FUN_004086c0`）将尚未设置的定位信息初始化为 `(-1, -1)`；之前 OpenBGI 使用 `(0, 0)`。已修改默认值及复制路径，并补充测试。用户验证后右上角矩形变为上下白条，问题未完全解决。
- 曾尝试让灰度遮罩作用于无 alpha 的 RGB 图像；实际读档后白块仍在，该尝试已撤回，不应作为根因。
- 用原版 x86 代码 `FUN_0042edd0` 和 Unicorn 测试 1320×760、原点 `(660,190)`、单位缩放，得到的包围尺寸与原点均与 OpenBGI 一致；这不等于完整验证整个显示管线。

## 待调查

- 比较原版和 OpenBGI 在该存档中白色对象的最终可见性、位置、缩放、遮罩与裁剪状态，确认是否有未实现的状态恢复或图层控制。当前无法断言白条的最终成因。
- 重点跟踪读档时 `white` 素材的创建、`92:12/16` 定位信息、`90:5C` 投影参数和后续显示对象操作；不要直接隐藏 `white` 资源，以免破坏正常转场。
- 必须使用独立数据目录复现，检查首次读档和再次读档，并与原版画面或原版执行轨迹比较。
