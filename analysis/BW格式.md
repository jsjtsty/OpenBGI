# BW 音频文件（`bw  `，声音资源）

【已验证：静态文件】`scripts/survey_bw.py` 对 `data03300`、`data04400/01/10/11/20`、`data05500` 共 **7520** 个成员逐个检查：全部是 **0x40 字节头 + 标准 Ogg Vorbis**，头里的字节数、总采样数、采样率、声道数与 libsndfile 读出的流信息全部一致（0 例不符）。读 `ac2_ML.c` 第 208880 行起的 `CBurikoWaveBox` 模型构造函数：读 0x40 字节头，检查第 4 字节起为 `"bw  "`，否则报 `0x11000001`；小于 0x40 字节报 `0x10000003`；用头里的声道数和采样率构造 16 位 PCM 的 WAVEFORMATEX（`FUN_004ca340`）。

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0x00 | u32 | 头长度，恒为 0x40 |
| 0x04 | char[4] | `"bw  "` |
| 0x08 | u32 | 后面 Ogg 流的字节数（= 成员长度 − 0x40，7520 个全成立） |
| 0x0C | u32 | 总采样数（每声道，与 Ogg 流一致） |
| 0x10 | u32 | 采样率（实测 44100） |
| 0x14 | u32 | 声道数（1 或 2；语音/SE 多为 1 或 2，BGM 为 2） |
| 0x18 | u32 | 循环标志（20 个成员为 1，其余为 0） |
| 0x1C | u32 | 循环起点（采样）；`data05500/bgm001` 为 11471 / 4783448 |
| 0x20–0x2F | u32×4 | 实测全为 0 |
| 0x30 | u32 | **模型类型**：0=PCM16、1=ADPCM4、2=HFADPCM8、3=OGG（`FUN_004c6c80` 的 `switch` 读它；7520 个成员全是 3） |
| 0x34–0x3F | u32×3 | 实测全为 0 |

Ogg 流从 0x40 起（`OggS`）。直接 `bw_extract.py <arc> <member> out.ogg` 即可得到可播放的 `.ogg`。

【已验证：机器码】头整体复制在 `CBurikoWaveBox` 对象 `+0x50..+0x8f`，所以头 0x18 → 对象 `+0x68`（循环标志），头 0x1C → `+0x6c`（循环起点采样）。**早先把类型字段写成 0x38 是错的**：真实文件头 0x30 处为 3，0x38 处为 0，与 `FUN_004c6c80` 的 `switch` 偏移一致。

**循环机制（已验证：反编译 + 虚表 + 真实头）**
- 四个流模型（PCM16/ADPCM4/HFADPCM8/OGG，虚表起点 `0x4f7b3c`、`0x4f80b8`、`0x4f8148`、`0x4f81dc`、`0x4f8270`）的第 2 项是读样本方法（`0x4cbfb0` 一类）。读到总采样数末尾时：先调虚表第 9 项，返回 0 就停；非 0 再调第 10 项“回到循环起点”，继续读。
- 第 9 项在所有模型里都是同一个函数 `0x44d740`：`return [this+0x68]`，即**头 0x18 就是循环标志**（早先在 `0x4c8000–0x4ce000` 范围里没找到读取点，因为这个读取函数在范围之外）。
- 第 10 项在 OGG 与另三个流模型里是同一个函数 `0x4cc7b0`：`this[0x1c] = this[0x6c]`，只把读位置设成循环起点采样，实际 seek 由下一次读取时的解码器完成。PCM16 模型另有自己的 `0x4cc9e0`。

**脚本参数如何覆盖头里的值**（`FUN_004c6c80`，B 档以上的 `A0:11` / `A0:12` 共用）：
- `FUN_004c6c80` 最后一个参数 `flags`：`flags & 1` 为真才调 `FUN_004cc280(this, flags & 2, 0)`，把 `+0x68 = flags & 2`、`+0x6c = 0` 写回去，**覆盖头里的循环标志和循环起点**；`flags & 1` 为假则保留头里的值。
- `A0:11`（`FUN_00495de0` → `FUN_004a2990` → `FUN_004c69e0`）固定传 `flags = 0`：**完全用头里的循环标志和循环起点**。
- `A0:12`（`FUN_00495f70` → `FUN_004a2cb0` → `FUN_004c6f30`）参数为 `(声道, 目录, 文件1, 文件2, 循环开关, 音量X, 声像Y)`，共 7 个。文件1 与文件2 同名（`strcoll` 为 0）时是单文件模式：`flags = 1`，循环开关非 0 时 `flags = 3`。即循环开关 = 0 → 不循环；≠ 0 → **整首从 0 开始循环**（循环起点被覆盖成 0，头里的起点不用）。
- 文件1 与文件2 不同名时是“前奏 + 循环段”双文件模式：创建 `0x9b8` 字节的对象（`FUN_004ce5e0`），要求两个头的类型相同且都是 3（OGG），循环开关存到对象 `+0x9b4`（`FUN_004ce8c0`）；播完文件1 后，`FUN_004ce8e0` / `FUN_004cec80` 把文件2 的头（对象 `+0x930..+0x96f`）复制到 `+0x50..+0x8f`，随后循环读文件2。
- `A0:12` 的调用现场：`scrsnd._bp` +0x4F6、`scrdrv._bp` +0x1A0A、`logwnd._bp` +0x2C88；`scrdrv` 里同一位置分支调用 `A0:11` 或 `A0:12`（后者压入两个文件名地址和一个变量作开关）。

【未验证】`scrdrv` 里由故事脚本哪条指令生成“前奏 + 循环段”的两个文件名，以及头标志为 1 的 20 个 BGM 在 `A0:11` 路径上的实际行为，没拿真实脚本对过。

OpenBGI 实现建议：用 libvorbis/stb_vorbis 解码，按头里采样率和声道数开流；两条路径各自实现：`A0:11` 用头里的循环标志和循环起点采样；`A0:12` 用脚本的循环开关（循环起点固定为 0），双文件时先播文件1、再循环文件2（文件2 的头提供它自己的采样数）。
