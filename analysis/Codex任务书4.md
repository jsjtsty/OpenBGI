沿用 `Codex任务书.md` 的第 0、1、4 节和 `Codex任务书2.md` 第 0 节（动态验证手段：`emu.py` / Unicorn、`disasm_fn.py`）。**不要修改 `D:\Projects\C++\OpenBGI\src\`、`tools\` 和 `tests\`**，实验脚本放 `analysis\scripts\`，产出放 `analysis\` 与 `analysis\out\`。结论标「已验证 / 静态推断 / 未知」，与原引擎用 Unicorn 对照通过的可标「已验证（与原引擎对照）」。

## 0. 现状（先读）

C++ 引擎已有窗口和渲染器，查看器 `obgi_view` 能显示 CBG 图和播放 BM 动画（解码与原版逐字节一致）。但 BM 的**播放速度**不知道，查看器暂时固定 30 帧每秒。已有的静态线索（见 `BM格式.md`、`视频.md`）：

- 头部 `0x24` 的「速率字段」：24 位 1280×720 样本（`shuchu` 298 帧、`ef_love` 1411 帧、`ef_shine` 1426 帧）为 60，32 位 1320×760 特效（4 帧）为 12 或 15。
- 引擎里只找到 `FUN_00406a30`（约 `ac2_ML.c` 第 4636 行）把它拷进信息块 `{宽, 高, 格式, 速率, 帧数}`，信息块由 `FUN_004aebc0` 之前的加载路径填写；**没找到任何用它控制播放的代码**。
- `FUN_00406a30` 的两个调用者 `FUN_0045c740`、`FUN_0045c9d0` 属于 `DCProcPlayMovieByMF`（Media Foundation 播 .mpg）一族，**不一定是 BM 的播放路径**。
- 帧是相对上一帧的差分，必须从第 0 帧顺序解码（已验证）。

## 1. 任务

### 任务 P：BM 的播放时序（最高优先级）

问题：原引擎播 `.bm` 时，每一帧显示多久？

1. 找出 BM 真正的播放路径：谁调用 `FUN_004aeb40`（取帧）、`FUN_004aebc0`；从脚本侧追到 `moviemngr`、`moviemngrbm` 两个系统脚本，以及 `ef_love.bm`、`ef_shuchu*.bm`、`shuchu.bm` 被调用时用的子 opcode（`91:xx` 一带，参见 `故事脚本用法.md`、`视频.md`）。
2. 确定帧号怎么推进：是脚本按计时器传帧号，还是引擎内部自己按固定间隔推进，还是和音频同步。找到时间源（`timeGetTime`、`GetTickCount`、帧计数器等）和换算公式。
3. 头部 `0x24` 是否参与：有读取就写出读取位置和用法；确认没人读就明确写「引擎不读」。若不读，给出实际使用的速度。
4. 验证：用 Unicorn 在原引擎里让一个 BM 播放若干个时间片，记录每次取帧的帧号和时间，推出帧率；或者至少对 `ef_shuchu_wh_a`（4 帧）和 `shuchu`（298 帧）各给出播放总时长。
5. 一并回答：播放到最后一帧后是停住、循环还是消失；由谁决定。

产出：更新 `视频.md` 和 `BM格式.md` 中的相关段落，并新增 `out\bm_timing.md`（证据链：函数地址、调用链、时间换算）。

### 任务 Q：BM 头部其余未明字段

1. `0x20`（样本 1 或 2）：已知与目标位图格式比较（`FUN_00406e00`），请确认它的取值含义（是否对应 BM 内部像素格式，以及 24 位源为何是 1、32 位源为何是 2）。
2. `0x2c`（样本 0 或 20）：是否被读取，用于什么。
3. `ef_shuchu_wh_a` 首帧 alpha 恒为 204：这是文件内容，还是引擎有额外的整体透明度（比如 BM 绘制时的叠加方式）？请确认 32 位 BM 在原引擎里是按哪种混合方式合成到画面上的（普通 alpha、加法、还是由脚本参数指定），以及 24 位 BM（如 `ef_love`，黑底光斑）是否使用加法混合。后一点直接影响我们的渲染器怎么画它们。

产出：更新 `BM格式.md`；混合方式部分写进 `视频.md`，并附上调用时传入的混合参数是如何得到的。
