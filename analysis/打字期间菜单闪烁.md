# 打字期间菜单闪烁（2026-11-09）

## 原因

《巧可甜恋3》开场对白期间，脚本随文字状态重建下方菜单的输入控制器。旧实现的 `90:B9 → panel_stop()` 同时删除按钮精灵，直到下一调度帧的新控制器启动才重建，产生一帧空白。Debug 单帧耗时更长时，这种空白更容易被看见；这一解释不依赖 GPU 性能假设。

无头状态日志确认第 1337、1339、1385 帧按钮消失，窗口自身保持显示，下一帧按钮恢复。原 C 版 `CodeSpace/openbgi/src/sys/panel.c` 的 `ButtonPanel_Stop()` 只清理输入、命中对象与控制器表，保留窗口画面；`sprpanel.c` 的 `SpritePanel_Stop()` 也不清空窗口子精灵。下一次 Start/Paint 才替换窗口子精灵。

## 修复

- `90:B9` 停止输入控制器时，将按钮显示状态转交给窗口的只绘制对象。
- 每个窗口仅保留一个只绘制对象；停止后不接收输入，不累积按钮精灵。
- 成功启动新面板或显式绘制时替换旧显示；保留的按钮继续跟随窗口的位置、透明度和隐藏状态。
- 删除窗口时沿用既有的只绘制对象清理路径。

## 无截图复现与证据

`--render-headless` 在确定性的虚拟时钟下走真实 GPU 呈现；默认无头运行仍跳过呈现。`OBGI_TRACE_MENU=1` 记录菜单状态变化与文字 reveal 进度，`OBGI_TRACE_BAND=x,y,w,h` 记录最新已呈现画面中指定区域的 FNV-1a 哈希，均不生成图片。

OBGI_TRACE_MENU=1 OBGI_TRACE_BAND='640,1015,900,50' \
OBGI_PRESS='500:1,750:1,1000:1' \
build/macos/src/Release/obgi_run '/Volumes/HDD-EXT/Games/巧可甜恋3' \
  --render-headless --frames 1450 \
