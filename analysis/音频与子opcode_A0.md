# 音频子系统与 A0 组子 opcode（任务 D，Claude 研究）

依据 `out/ac2_ML.c`：A0 包装 FUN_00495c90–FUN_00496880（159373 行起）→ 参数校验 FUN_004a85c0/8610/8670/86d0 → 管理层 FUN_004a26e0–FUN_004a2fe0 → 加锁包装 FUN_004c8xxx（锁 0x531368）→ 实现 FUN_004c6xxx/4c7xxx。全部【静态推断】，没有动态验证。

## 结构

两个并行的“通道库”，各通道状态结构 0x44 字节：

| 库 | 通道数 | 状态表 | 典型用途（推断） | 校验函数 |
|---|---|---|---|---|
| 库 A | 16（0..0xF） | 0x00533588 + ch*0x44（对象指针在 +4） | BGM/长流（有位置查询 FUN_004cc250、暂停） | FUN_004a86d0（ch ≤ 0xF） |
| 库 B | 128（0..0x7F） | 0x00531388 + ch*0x44 | SE/语音（短音） | FUN_004a85c0（ch ≤ 0x7F） |

- 音量统一为 **0..0x80**（>0x80 钳到 0x80；`FUN_004a8610/8670` 校验 ≤0x80）。0x40 作为默认/中间值（库 A 的“位置”参数以 0x40 为中心，见 A0:17）。
- 管理层保存“配置音量”数组：库 A `DAT_0058f570[16]`、库 B `DAT_0058f370[128]`；设置时若静音标志 `DAT_0058f5b0==0` 则立即下发到底层。
- 淡入淡出由时间戳实现：记录 `GetTickCount()` 起点、终点 = 起点 + 毫秒、起始音量与目标音量（字段 +0x...b8/bc/c0/c4，库 B 为 +0x...b8..c8），由每帧的混音更新函数插值（更新函数未读）。
- 底层是 DirectSound（`DSOUND.dll` 动态加载，`DAT_00531364 & 3 != 3` 时所有调用返回 0x14=未初始化；通道越界返回 0x15；通道未打开返回 0x13；文件找不到 0x0C；其它 0x0E）。声音对象有虚函数：+8 播放、+0xC 暂停开关、+0x10 停止/暂停、+0x14 声像、+0x18 音量、+0x1C 销毁并返回对象、+0x20 状态。
- 声音文件由 `FUN_004c9500` 打开（`CBurikoWaveBox*` 解码器：PCM16、ADPCM4、HFADPCM8、OGG；游戏实际使用 `bw  ` 头 + Ogg）；查找顺序：先目录 `DAT_00547db8`，找不到(0x0C)再用 `DAT_005470a0`；脚本若给出归档名参数则经 FUN_00407910 在指定归档内找成员。

## A0 子 opcode（弹栈顺序为先弹后者，括号内按“脚本压栈先→后”）

| 子 opcode | 静态位置 | 含义（推断） |
|---|---|---|
| `A0:00` | 0 | 返回 0x14（压入常量，未初始化状态占位） |
| `A0:08` | 4 | (库A通道 ch, 音量) 设置库 A 配置音量，FUN_004a26e0 |
| `A0:09` | 13 | (库B通道 ch, 音量) 设置库 B 配置音量，FUN_004a2710 |
| `A0:10` | 0 | (库A ch, 文件名, 参数) 打开并播放，FUN_004a2790 → FUN_004c85d0(ch, 路径, 参数, 0x40, double)；0x0C 且存在备用目录则重试；0x0C/0x0E 抛脚本错误 |
| `A0:11` | 6 | **(库A ch, 目录/归档前缀串, 文件名串, 值X(≤0x80), 值Y(≤0x80))**；`scrsnd._bp` 现场为 `(ch, "代码内字符串", 变量文件名, 变量, 64)`，Y=64。FUN_004a2990：前缀为空则依次遍历两个默认目录；当 FUN_0049c270 非 0 时创建 0x64c 字节的异步等待对象（FUN_0045d3f0，返回调度码 2，等待加载完成），否则同步 |
| `A0:12` | 3 | **(声道, 目录前缀, 文件1, 文件2, 循环开关, 值X, 值Y)**（FUN_004a2cb0 → FUN_004c6f30）。同名=单文件：开关 0 不循环，非 0 整首从 0 循环；不同名=前奏+循环段双文件（均须为 OGG 型）。详见 `BW格式.md` 的循环机制一节 |
| `A0:14` | 20 | **(库A ch, 播放开关)**：传入 `值==0` 给虚函数 +0xC（暂停开关）；`scrsnd` 现场在加载前 `A0:14(ch,0)`（暂停）、加载后 `A0:14(ch,1)`（开始播放）【由调用序列佐证】 |
| `A0:15` | 2 | (地址) 查询：压入库A 状态(+0x20)，并向地址写播放位置(FUN_004cc250) |
| `A0:16` | 24 | (ch, 目标音量, 毫秒) 淡到目标音量，FUN_004c88d0→FUN_004c7810 |
| `A0:17` | 0 | (ch, 值 0..0x80) 声像：`(值−0x40)*常数` 传入虚函数 +0x14 |
| `A0:18` | 0 | (ch, 毫秒) 淡入（目标 0x80），FUN_004c6410 |
| `A0:19` | 11 | (ch, 毫秒) 淡出（目标 0），FUN_004c6470 |
| `A0:1C` | 0 | (ch, 值) 库A 另一层音量，FUN_004c6830 |
| `A0:20` | 10 | **(库B ch, 目录串, 文件名串)** 加载 SE/语音：创建 0x678 字节的异步加载对象（FUN_00442190），返回调度码 2（等加载完成）；之后用 `A0:24` 启动播放【`title._bp` 0xa56 现场佐证】 |
| `A0:21` | 5 | 同上，另带毫秒数（×常数）与一个数值 |
| `A0:22` | 4 | (库B ch) 清空 0x40 字节配置并停止销毁，FUN_004a2f70 → FUN_004c8250 |
| `A0:23`、`A0:27`、`A0:28` | 0/0/1 | 同类“带等待的加载/播放”（A0:28 经 FUN_0045d230） |
| `A0:24` | 30 | **(库B ch, 音量, 声像)**，`title._bp` 现场 `A0:24(24, 128, 64)`＝通道 24、音量 128(0x80 满)、声像 64(0x40 居中)；紧跟在 `A0:20` 加载之后。FUN_004c66d0：FUN_004c77c0(ch, 声像参数)，字段 +0x3b0=音量，音量层设 0x80，对象虚函数 +0x10 → +8 启动；成功压回查询值 |
| `A0:25` | 14 | (库B ch) 虚函数 +0x10（停止/暂停） |
| `A0:26` | 4 | (库B ch, 毫秒) 淡出，FUN_004c64d0 |
| `A0:2C` | 0 | (库B ch, 值) 库B 另一层音量，FUN_004c68a0 |
| `A0:2F` | 0 | (库B ch) 查询状态 |
| `A0:80/81/84/85/86/C0` | 0 | 占位/静音相关小项（FUN_0049cbd0、FUN_004a30d0 等），未读 |

## 对 OpenBGI 的含义

- 抽象成两个库：16 条“流”通道（BGM）和 128 条“点”通道（SE/语音），每条通道：音量(0..0x80)、声像、淡入淡出（毫秒）、暂停、位置查询、结束检测。SDL3 的音频流 + 自写混音器即可；Ogg 解码用 stb_vorbis/libvorbis。
- 等待型 opcode（A0:11/20/21/23/27/28）通过脚本线程“等待对象”挂起，结束条件是加载/播放完成，需与调度器协议（`VM分析.md`、`子opcode语义表.md` 的等待协议）配合。
- 淡入淡出的时间基是毫秒，由每帧更新；实现可直接按线性插值。
