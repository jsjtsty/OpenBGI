# 系统资源与文件校验（任务 K）

## BGI.hvl

【已验证：样本】当前 `BGI.hvl` 为 1936 字节，前 16 字节中 `+0x00` 是 `BHV_____`，`+0x0c` 是条目数 30；随后每项 `0x40` 字节，前 `0x38` 字节存零结尾文件名，最后 8 字节为两个小端校验字。`16+30*0x40=1936`。`FUN_00401c90` 也支持 `BHV_V2__`：每项 `0x100` 字节，校验值在 `+0xf8`，但当前没有该格式样本。

【静态推断；五个实际文件对照通过】`FUN_00401b70` 按输入字节顺序更新两个 32 位值，初值均为零。记字节 `c`、第一字 `a`：`a=(a*233+c) mod 2^32`；第二字的四个字节分别累计 `a&255` 的和与异或、`c` 的和与异或，所有加法按 8 位截断。EXE 中的安装文件复制流程（`ac2_ML.c` 约 138200–138285 行）按名称不区分大小写查找条目，并与复制过程中计算的两字比较；不符时标记文件损坏。这是文件校验用途，不必推定为密码学哈希。

```powershell
py -3 analysis/scripts/hvl_verify.py 'E:\Games\Amairo Chocolate 2\BGI.hvl' 'E:\Games\Amairo Chocolate 2' ac2_ML.exe
```

同样分别传 `autoload.arc`、`sysprg.arc`、`data01100.arc`、`data06000.arc` 均与清单一致。不传最后的筛选条件会逐个读取所有条目，归档很大，耗时较长。当前没有声称校验了所有大文件；缺失文件会报告 `MISSING`。

## SGCnf 系统资源

【已验证：175 个样本】`sysgrp.arc` 内名称以 `SGCnf` 开头的 175 个成员先用 `DSC FORMAT 1.00` 解压；解出的数据均满足 **16 字节头 + 宽×高×每像素字节数**，其中 169 个 32 位、6 个 24 位。它们是界面位图资源，名称中的 `Cnf` 不代表内容是键值配置文本；`SGCnf000100_en` 输出图片显示文本按钮。列表在 `out/sgcnf_manifest.tsv`。例如 `SGCnf000000_en` 为 1280×720×32 位，长度为 3,686,416 字节。

| 解压后偏移 | 字段 | 依据 |
|---|---|---|
| `0x00`, `0x02` | u16 宽、高 | 175 个长度关系及 `FUN_004028e0` |
| `0x04` | u16 位深 | 样本 24 / 32；引擎 `FUN_00402110` 解释格式 |
| `0x06` | u16 编码标志 | `FUN_004028e0` 对 0 直接使用，对 1 调用 `FUN_00406680`；样本均为 0 |
| `0x08–0x0f` | 标志或保留 | 样本均为零；部分其他格式在 `+0x0a` 使用标志，完整含义未知 |
| `0x10` | 像素 | 样本按 BGR/BGRA 顺序解释；32 位通道保留 alpha |

复现并导出一个样本：

```powershell
node analysis/scripts/survey_sgcnf.js 'E:\Games\Amairo Chocolate 2\sysgrp.arc'
node analysis/scripts/extract_dsc.js 'E:\Games\Amairo Chocolate 2\sysgrp.arc' SGCnf000100_en analysis/out/SGCnf000100_en.dec
py -3 analysis/scripts/sgcnf_png.py analysis/out/SGCnf000100_en.dec
```

图片和解包内容仅保存在 `analysis/out/`。逐样本的长度一致不构成所有像素语义的逐字节动态验证。
