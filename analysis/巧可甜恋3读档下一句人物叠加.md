## 已定位的合成错误

脚本先以 `90:57` 将人物精灵 `0x80000004` 绑定到临时位图 10598。在虚拟时间 27296–27536 ms，每隔 16 ms 更新这张位图：

```text
90:18 dst=10598 src=10534 effect=0x80 level=0
90:19 dst=10598 src=10502 gray=-1 param=0 level=16,32,...,245,256
```

即先恢复旧表情，再按进度混合新表情，最后交给人物精灵显示。旧实现的 `90:19` 忽略灰度图缺失时的特殊语义，直接将 `param=0` 当作普通混合模式 0；该模式对 ARGB 图执行 source-over，忽略 `level`，既不能逐步替换旧图，也会累计透明区域的覆盖。这解释了重影及渐变突变。

直接核对 `amachoco3.exe` 原版代码：位图包装函数 `0x44D9E0` 在找不到灰度位图后，裁剪矩形并在 `0x44DB17` 调用 `0x456340`，参数为 `(dst, dst, src, level, parallel=1)`。后者是 CrossfadeTo，RGB32 做线性插值，ARGB32 做 alpha 加权交叉渐变。第二作反编译文件 `analysis/out/ac2_ML.c` 中的同源函数为 `FUN_00402df0 → FUN_0040d500`。旁边 C 版参考实现对缺失灰度图的说明与这些原始二进制不一致，因此本次以原始 EXE 为准。

`analysis/scripts/probe_ac3_crossfade.py` 用 Unicorn 直接执行第三作 `0x456340`，不启动游戏窗口、不生成图片，并用 EXE SHA-256 限制适用版本。320 个 RGB/ARGB 样例与整数模型相比，alpha 全部一致，317 个结果完全一致，3 个样例 RGB 最大差 2，来自原版倒数近似/取整。

## 修复

`90:19` 缺失灰度图时改走 `Display::crossfade_slot()`。使用已有 GPU blit 管线的内部运算，裁剪后将当前目标像素与源像素做 CrossfadeTo；自重叠来源先在 GPU 上复制，避免读写别名。普通脚本 blend mode 的支持范围保持原样。共用同一个 GLSL CrossfadeTo 函数，确保精灵双图渐变和位图渐变使用相同公式。

此路径没有新增 CPU 回读或逐帧 CPU 图像处理。有效灰度图的另一分支不属于本次修复范围。

## 仍存在的同步停顿

修复后一次 Release 无头回放，对 27280–28000 ms 共 46 帧记录 tick/present 耗时：

- 27280 ms 主线程约 50.8 ms，包含人物资源载入与初始化。
- 27568 ms 主线程约 20.5 ms，包含下一段音频加载。
- 同段 present 中位约 4.1 ms，最大约 8.4 ms。

这些是单次带日志、带离屏回读运行的观测，不能当作交互模式 GPU 时间或严格性能基准。它们表明除混合错误外，还存在同步资源加载引起的实际停顿；本次未改造首次图片/音频加载的异步调度，也不能据此声称全部动画卡顿已消除。

同一路径的 Debug 回放在 27280 ms 主线程耗时约 131.1 ms，同段呈现最高约 10.3 ms。该差异进一步支持同步资源准备是这两次运行中实际长帧的来源。

路径动画的 duration 单位也已核对原版 `wait_tween.c`，为毫秒；未因注释中误写 frames 而修改其时长。
