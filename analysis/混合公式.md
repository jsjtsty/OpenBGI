# CPU 位图混合公式（任务 F，Claude 研究：从 x86/SSE 汇编读出）

方法：`py -3 scripts/disasm_fn.py <VA>`（capstone 直接反汇编 exe）。读的是每个模式的**标量/SIMD 内核本体**，而非反编译 C。符号：`d` = 目标像素通道值（0..255），`s` = 源通道值，`P` = 调度器传入的 alpha 参数（0..0x100，下文称“强度/透明度参数”），`sa` = 源 alpha 通道。所有结果最后 `packuswb` 饱和到 0..255。

## 位图像素格式（`bitmap[4]`，每像素字节数表 `0x501fd0 = {2,4,4,1,4,4,6,4}`）

| 格式 | 含义 |
|---|---|
| 0 | 16 位 |
| 1 | 32 位 BGRX（无 alpha，第 4 字节忽略） |
| 2 | 32 位 BGRA |
| 3 | 8 位（灰度/遮罩） |

（`渲染管线.md` 里“0=8位、1=24位、2=32位”的写法有误，以此为准。）每个模式函数按（源格式，目标格式）分发；下面给出每个模式最典型组合的公式。整图混合还有按 `0x534688`（`91:0A` 设置，默认 0 且脚本里无调用）切换的路径，见模式 2、3 和“选项”一节。

## 参数 `P` 的约定因模式而异

调度器 `FUN_0040b9d0` 把 `P`(0..0x100) 原样传给内核。不同内核对 `P` 的含义不同（已从内核确认）：

| 模式 | `P` 的含义 |
|---|---|
| 1、0x20、5、0xC0 | **透明度**：`P=0` 完全不透明（模式 1 时 `P==0` 直接走拷贝），`P=0x100` 完全透明；内核内部用 `0x100−P` 作权重 |
| 2、3、4、6、7、8、9、0x21–0x27 | **强度**：`P=0x100` 为满强度 |

`0x21–0x27` 是对应模式把 `P` 换成 `0x100−P` 再调用（即反向参数）。显示对象（`CDspObj`）如何得到 `P`，见下面“CDspObj 到 P 的换算”一节。

## 已读通的模式

### 模式 0 —— 拷贝 / 按自身 alpha 叠加（`FUN_0040c240`）
按（源格式，目标格式）分发，忽略 `P`（已核对汇编，修正了此前“整块拷贝”的说法）：

| 源 → 目标 | 函数 | 行为 |
|---|---|---|
| 同为 32 位无 alpha（1→1） | `0040be00` | 整块 memcpy |
| 1 → 2 | `0040c090` | 逐像素 `s \| 0xFF000000`（补不透明 alpha） |
| 2 → 1 | `0040c300` | **不是预乘**（动态验证后更正）：把源按自身 alpha 混进目标，相当于模式 1 的 `P=0`：`w=sa>>1`，`out=d+(((s−d)·w)>>7)`，`sa<2` 跳过，目标 alpha 不变；标量尾部在 `sa==255` 时直接覆盖，**SIMD 成对路径没有这个特例**（`sa=255` 时只到 `w=127`），两者最多差 2 |
| 2 → 2 | `0040c480` | **Over 合成，用源像素自己的 alpha**：`sa==0` 跳过；`sa==0xFF` 直接覆盖；其余与模式 1 同一套 `a_o / w_s / w_d` 公式（SIMD 用 `rcpps` 和浮点，标量尾部用 `div`） |
| 0（16 位）→ … | `0040c290` | 16 位路径（未逐条核对） |

所以模式 1 在 `P==0` 时就等价于“按源 alpha 的 Over”，不是不透明覆盖。

### 模式 1、0x20 —— 普通 alpha 混合（`FUN_0040c6c0`，内核 `0040c850/c940/ca80/cda0`）
最典型组合 源BGRA→目标BGRA（`FUN_0040cda0`）：设 `T=P`（透明度参数），`sa'=sa·(256−T)/256`（0..255 标度）：
```
a_o  = sa' + a_d·(1 − sa'/256)                 # 目标 alpha 也参与
w_s  = 256·sa'/a_o ,  w_d = 256·a_d·(1−sa'/256)/a_o     # a_o==0 时加 1 防除零
C_o  = (C_d·w_d + C_s·w_s) >> 8                 # 每个颜色通道
alpha_out = floor(a_o) | min\| min(255, (sa·ws + da·wd) >> 8)      # 动态验证发现的“或”，见“动态验证”一节
```
源 alpha 为 0 的像素跳过（整对像素 alpha 全 0 时不写）。标量尾部用整数除法实现同一公式（`div`），SIMD 路径用 `rcpps`（近似倒数）→ 两条路径可有 ±1 误差。
`P==0` 走模式 0（见上，BGRA→BGRA 即按源 alpha 的 Over）；`P>=0x100` 不处理。源BGRX→目标BGRX（`0040c850`）退化为常数 alpha 的 `d + (s−d)(256−T)/256` 形式（未逐条核对）。

### 模式 2 —— 加法（线性减淡），`FUN_0040dce0`，BGRA→BGRA 内核 `0040e280`
```
if (0x534688 == 1):  out =floor(a_o) | min(255, d + s·P/256)      # 按通道（含 alpha 通道），忽略源 alpha 权重，仅 sa==0 的像素对跳过
else:                out =floor(a_o) | min(255, d + s·f/128),   f = ((sa>>1)·P)>>8   # 即 s·sa·P/65536，按源 alpha 加权
```
（`psllw 4 → pmulhw` 实现 `s·P/256`；`packuswb` 后 `paddusb` 饱和加。）

### 模式 3 / 0x22 —— 减法，`FUN_0040e560`，BGRA→BGRX 内核 `0040e590`
`out = max(0, d − s·f/128)`，`f = ((sa>>1)·P)>>8`（`psubusb`）；源 alpha 低 7 位以外的位不使用（`sa>>1`）。`sa<2` 的像素被跳过。

### 模式 4 / 0x23 —— 正片叠底（Multiply），`FUN_0040e760`，BGRX→BGRX 内核 `0040e7d0`
`xmm5 = {256,256,256,0}`，`xmm4 = {P/2,…}`：
```
t   = (s − 256)·(P/2)                   # 负值
out = d + ((t · 2d) >> 16)              # pmulhw
    = d·(1 − (256−s)·P/65536)           # P=0x100: out = d·s/256
```
（alpha 通道乘数为 0，不变。）其余格式组合 `0040e8f0/ea00/ebe0` 同族（含源 alpha 加权与 8 位版本，未逐条核对）。

### 模式 5 / 0xC0 —— 带亮度衰减的拷贝，`FUN_0040ed50`，内核 `0040ede0`（BGRX→BGRX）
`out = s·(0x100−P) >> 8`（写入目标，**不与 d 混合**）：整体乘以 `(256−P)/256` 后覆盖，用于“渐暗/渐亮拷贝”。其它格式组合 `0040eec0/f040` 带源 alpha 查表（`pextrw`/`pmovmskb`）和整数 `div`，大意相同但按 alpha 处理（未核对）。

### 模式 6 / 0x24 —— 滤色（Screen），`FUN_00416e40`，内核 `00416e80`（BGRX→BGRX）
```
s' = s·P/256
out = d + s' − (s'·d >> 8)                # = 1−(1−d)(1−s')
```

### 模式 7 / 0x25 —— 按源 alpha 压暗（`FUN_00418260`，内核 `004182d0`，BGRA→BGRX）
预表 `tab[i] = 256 − ((i·P) >> 8)`（i = 0..255）：
```
out = d · tab[sa] >> 8                    # 每个颜色通道；sa==0 的像素对跳过
```
即 `d·(1 − sa·P/65536)`：用源的 alpha 通道当“黑色叠加层”的不透明度（阴影/暗角）。注意：目标带 alpha 或为 8 位时行为不同，见后面“16 位 / 8 位 / 混合格式路径”表。

### 模式 8 / 0x26 —— 叠加（Overlay，以目标为基色），`FUN_00417200`，内核 `004173c0`
`xmm6 = 127`，掩码 `m = (d > 127)`：
```
r = m ? 2(s+d) − 255 − (s·d >> 7)   :   (s·d) >> 7
out = d + ((r − d)·P) >> 8             # 以 P 做插值
```
即标准 Overlay：`d<128: 2sd/256`，`d≥128: 255 − 2(255−s)(255−d)/256`。

### 模式 9 / 0x27 —— 强光（Hard Light，以源为基色），`FUN_00417810`，内核 `004179d0`
与模式 8 相同，仅掩码改为 `m = (s > 127)`。

## 其余模式（已读汇编）

所有内核都先把两张位图的宽高取小（`min`）再逐行处理，格式编号：0=16 位(RGB555)，1=32 位无 alpha，2=32 位带 alpha，3=8 位。

### 模式 0x40 —— 擦除（destination-out 式抠洞），`FUN_0040f170`
以**源**为遮罩，把目标对应像素**置 0**（全通道含 alpha，即透明黑），不做混合：
- 源 16 位 → 目标 16 位（`0040f1c0`）：源字 ≠ 0 则目标字 = 0。
- 源 32 位无 alpha（`0040f230`）：源 B+G+R ≠ 0（非纯黑）则目标 = 0。
- 源 32 位带 alpha（`0040f2b0`）：参数 `P≠0` 时源 alpha ≠ 0 即擦除；`P==0` 时只有源 alpha == 0xFF 才擦除。
- 其余格式组合不处理。用途推测：用遮罩图在图层上挖洞。

### 模式 0x41 —— 清除矩形，`FUN_0040b940`
源位图只提供**范围**：取目标矩形与源矩形的交集（`409f10` 构造矩形、`409e90` 求交），交集非空就把目标那一块**写成 0**（`40b4e0`，MMX/SSE 非时序存储）。不读源像素，不用 `P`。

### 模式 0x80 —— 格式转换拷贝，`FUN_0040c040`（第三参数固定 0）
同格式 → memcpy（`0040be00`）；1→2 补 alpha=0xFF（`0040c090`）；2→1 预乘到黑（`0040c140`，同模式 0 的 2→1）；**8 位 → 32 位带 alpha**（`00412100`）：`out = (灰度 << 24) | (color & 0xFFFFFF)`，这里 `color=0`，即把 8 位图当 alpha 通道、颜色全黑。其余组合不处理。用途：把灰度遮罩转成 alpha 图。

### 模式 0xC1 —— 向白色渐变的拷贝，`FUN_00411e40(…, 0xFFFFFF, P)`
要求源、目标格式相同（1/2 走 `00411f90`，0 走 `00411e90`）。逐通道：
```
out_c = (s_c·(256−P) + C_c·P) >> 8      # C = 0xFFFFFF，B/G/R 三个通道，paddusw 饱和
out_a = s_a                              # alpha 通道系数固定 256，原样保留
```
结果直接写入目标，**不与 d 混合**。`P=0` 是原样拷贝，`P=0x100` 是纯白（保留 alpha）。它是模式 5/0xC0（向黑渐变，`out=s·(256−P)>>8`）的白色版本；`FUN_00411e40` 的颜色参数为 0 时直接转给 `40ed50`，所以 0xC0 就是它的 `color=0` 情形。

### 模式 0xF0 —— 两图交叉淡化，`FUN_0040d000`
- `P==0`：等同模式 0x80（带格式转换的拷贝）。
- `0<P<0x100`，源为 32 位（1 或 2，`0040c850`）：令 `w=P>>1`（0..128），逐通道含 alpha：
  `out = s + (((d − s)·w) >> 7)`（算术右移），饱和到 0..255。即源和目标的线性插值，**P 是目标的权重**：`P=0` 得源，`P→0x100` 得目标。
- 源为 16 位（`0040d050`，RGB555）：`out = (s·(256−P) + d·P) >> 8`，每通道独立，掩码 `0x7C00/0x03E0/0x001F`。
- `P≥0x100`：不处理。

### 模式 0xFF —— 通道提取，`FUN_00412560`
此处第三参数 `P` 被当作**通道号**：
- `P ≥ 4`：退化为模式 0（`40c240`）。
- `P < 4` 且源为 32 位（`00412590`），目标写为不透明图（alpha=0xFF）：
  - `P=0`：`0xFF000000 | B`（只留蓝，G/R 为 0）
  - `P=1`：`0xFF000000 | (src & 0x0000FF00)`（只留绿）
  - `P=2`：`0xFF000000 | (src & 0x00FF0000)`（只留红）
  - `P=3`：`0xFF000000 | A·0x010101`（把 alpha 变成灰度图）
- 用途：把某个通道提成遮罩（尤其 `P=3` 抽 alpha），多半用于 wipe 遮罩或调试。

## 16 位 / 8 位 / 混合格式路径（已读汇编）

约定：16 位像素是 RGB555（`R=0x7C00 G=0x03E0 B=0x001F`，第 15 位不用）；**16 位源的像素值 0 视为透明（色键），一律跳过**。各内核按行从右往左处理，不影响结果。

| 模式 | 格式（源→目标） | 函数 | 公式 |
|---|---|---|---|
| 0 | 16→16 | `0040c290` | 源字 ≠ 0 则覆盖目标字，否则不动 |
| 1 / 0x20 | 16→16 | `0040c750` | 源字 ≠ 0：每通道 `(s·(256−P) + d·P) >> 8`（先掩出通道再算，已核对不会串位） |
| 1 / 0x20 | 2→1（主合成路径：带 alpha 源画到无 alpha 画面） | `0040ca80` | 先建 128 项表 `w[i] = (i·(256−P)) >> 8`，`i = sa>>1`；`sa ≤ 1`（`sa & 0xFE == 0`）跳过；`out = d + (((s−d)·w[sa>>1]) >> 7)`，算术右移，B/G/R 三通道 |
| 1 / 0x20 | 1→2（无 alpha 源画到带 alpha 目标） | `0040c940` | 同 Over 公式，源 alpha 取常数 `(256−P)·255/256`，目标 alpha 参与，整数 `div`（16.16 定点） |
| 2 | 16→16 | `0040dd60` | 源字 ≠ 0：每通道 `min(满值, (s_c·P >> 8) + d_c)`（满值 31），这里 `P` 就是强度，没有 `/128` 形式 |
| 5 / 0xC0 | 16→16 | `00411e90`（颜色 0） | 每通道 `(s·(256−P) + C·P) >> 8`，无色键跳过；0xC1 同函数，`C=0xFFFFFF` 转成 5 位通道 |
| 0xF0 | 16→16 | `0040d050` | `(s·(256−P) + d·P) >> 8`，每通道，无色键跳过 |
| 0x40 | 16→16 | `0040f1c0` | 源字 ≠ 0 则目标字 = 0 |
| 4 | 8→8 | `0040ebe0` | 真乘法加线性混合：`m = ((s·d+1)·0x101) >> 16`（≈ `s·d/255`），`out = d + (((m−d)·P) >> 8)`（字节回绕加）。`P=0x100` 时即 `s·d/255` |
| 7 | 2→3（目标 8 位），`P<0x100` | `00418770` | `sa==0` 跳过；标量 `out = d·(0xFF00 − sa·P) >> 16`；SIMD 路径等价于 `d·(256 − (sa·P>>8)) >> 8`，两者最多差 1 |
| 7 | 2→3，`P=0x100` | `004188b0` | `out = d·(255 − sa) >> 8`，`sa==0` 跳过 |
| 7 | 2→2（目标带 alpha），`P<0x100` | `004184b0` | **只改目标的 alpha**，颜色不变：`A_out = A_d·(0x10000 − sa·P) >> 16` |
| 7 | 2→2，`P=0x100` | `00418620` | `A_out = A_d·(256 − sa) >> 8`，颜色不变 |

要点：
- 模式 7 对 32 位无 alpha 目标是压暗颜色（上面已读的 `004182d0`），对带 alpha 目标是**压低目标 alpha**（destination-out，用源 alpha 擦掉目标的不透明度），对 8 位目标是压暗灰度。
- 模式 8、9 只支持 32 位无 alpha → 32 位无 alpha（分发器里没有别的分支），所以没有 16/8 位变体。
- 模式 3、6 的分发器只接受 2→1 和 1→1（见上文，没有 16 位/8 位变体）。
- 2→1 的主合成（`0040ca80`）永远到不了完全不透明：`sa=255,P→1` 时 `w=127`，覆盖率 127/128。要逐位一致必须复刻这个 `>>1` 与 `>>7` 的量化，不能改成标准的 `sa/255`。

### 32 位混合格式组合（已读汇编）

通用约定：`w[i]` 指内核启动时建的 128 项表 `w[i] = (i·P) >> 8`（`i = sa>>1`，`P≥0x100` 时用 `w[i]=i`，即 `0x5346b0` 全局表）；源 alpha 满足 `sa & 0xFE == 0`（0 或 1）的像素跳过；"B/G/R" 表示只处理三个颜色通道。

| 模式 | 源→目标 | 函数 | 公式 |
|---|---|---|---|
| 2 | 1→1 | `0040de90` | 源 B+G+R == 0（纯黑）跳过；否则每通道 `min(255, d + (s·P >> 8))` |
| 2 | 1→2 | `0040df90` | 同上，另外目标 alpha `A_d' =floor(a_o) | min(255, A_d + P)` |
| 2 | 2→1 | `0040e0b0` | `out =floor(a_o) | min(255, d + ((s·w[sa>>1]) >> 7))`（饱和加，B/G/R） |
| 4 | 1→2 | `0040e8f0` | `m = (s·d) >> 8`；`out = d + (((m−d)·(P>>1)) >> 7)`；**目标 alpha 不变**（alpha 通道的系数为 0） |
| 4 | 2→1 | `0040ea00` | `m = (s·d) >> 8`；`out = d + (((m−d)·w[sa>>1]) >> 7)`；用源 alpha 当混合权重 |
| 5 / 0xC0 | 2→1 | `0040eec0` | `s' = (s·(256−P)) >> 8`（向黑色衰减）；`out = d + (((s'−d)·(sa>>1)) >> 7)`；注意这里表是 `i→i`，`P` 不进表 |
| 5 / 0xC0 | 2→2 | `0040f040` | 先令 `Q = 256−P`；`den = 256·sa + (256−sa)·A_d`；`w_s = (sa·Q << 16)/den`；`w_d = ((256−sa)·A_d << 16)/den`；`C_o = (C_s·w_s + C_d·w_d) >> 16`；`A_o = den >> 8`。即 Over 合成，但只有**源颜色**的权重乘了 `Q`（颜色变暗，alpha 不受 `P` 影响）；`sa==0` 跳过；整数 `div` |
| 6 | 2→1 | `00416fd0` | 表 `w[i] = (i·P) >> 8`，**i = sa（0..255，256 项）**；`s' = (s·w[sa]) >> 8`；`out = d + s' − ((s'·d) >> 8)`；`sa==0` 跳过 |

对前面表格的修正与补充：
- 模式 4 在 1→1（`0040e7d0`）与 1→2（`0040e8f0`）写法不同：前者是 `d(1 − (256−s)P/65536)`，后者是“真乘法 `m=(s·d)>>8` 再与 `d` 线性插值，权重 `P>>1`（0..128）”。`P=0x100` 时两者都得到 `s·d/256`，其它 `P` 的舍入不同。
- 模式 2 和 4 的 2→1 路径用的是 `sa>>1` 的 7 位权重，同模式 1 的主合成一样，满不透明时权重最多 127/128。
- 模式 5 的 2→2 对 `P` 的用法与 2→1 不同：2→1 先把整个源（含与 `d` 混合的权重）按 `256−P` 衰减，2→2 是只衰减颜色权重、alpha 照常。

所有 32 位组合现已核对完。

## CDspObj 到 P 的换算（`FUN_004213c0`，已读）

对象上有三个数：`A = +0xb4`（脚本里的“alpha”，`90:56` 第 6 参数 / `90:32` / `90:38 propId=2`）、`B = +0xb8`（`90:34` 设置，**仅当 `+0x114 & 1`** 才生效）、`C = +0xbc`（`90:39` 设置）。构造函数（`FUN_0041fe80`）的默认值：**混合模式 `+0xb0 = 0x80`、`A = 0`、`B = 0`、`C = 0x100`**。传给 `FUN_0040b9d0` 的 `P` 为：

| 对象混合模式 | `P` |
|---|---|
| 1、0x20、0x21、0x22、0x23、0x24 | `P = 0x100 − (((0x100−B)·(0x100−A)·C) >> 16)` |
| 2、3、4、0xC0、0xC1 | `P = ((0x100−B)·C·A) >> 16` |
| 其它（0x80、5、6、7、8、9、0x25–0x27、0x40、0x41、0xF0、0xFF） | `P = A`（直接取） |

结论：
- 对**模式 1 系列**，脚本传的“alpha”实际是**透明度**：`A=0` 不透明（默认），`A=0x100` 完全不显示。`B`、`C` 是两个额外的“可见度”因子（`0x100` 为 1，`B` 取 0 时中性，`C` 取 `0x100` 时中性），三者相乘。`90:56` 的 alpha 参数在系统脚本里常见值是 0 和 256，与此吻合。
- 对**模式 2、3、4、0xC0、0xC1**，`A` 是强度，`A=0` 无效果；`B` 作为 `0x100−B` 的衰减，`C` 作为乘数。
- 新建对象默认模式是 **0x80**（格式转换拷贝，忽略 `P`），所以不设置混合模式的对象就是原样拷贝，`A` 不起作用。
- 混合模式的设置路径：`90:56` 第 5 参数（范围检查 `FUN_004a88f0`）或 `90:38 propId=1`；`B` 的写入还要求 `+0x114` 位 0。【静态读码，已追】构造函数 `FUN_0041fe80` 调用 `FUN_00421ee0(this,0,1)`，掩码 0 视为全 1、值非 0 即**把 `+0x114` 全部置 1**，所以位 0 默认就是 1，`90:34` 的 B 默认生效；脚本可用 `90:38 propId=0xFFFF`（掩码、开关）清除。

## 脚本里实际用到哪些混合模式（静态统计）

脚本：`scripts/blend_usage.py`（用 `bgi_dis.py` 线性反汇编 114 个 `_bp`，抓 `90:56`/`90:38` 前面的立即数参数）。

- `90:56` 共 114 处，其中参数全为立即数的 111 处：**混合模式 1 共 110 处，0x80 共 1 处**（`scrgrp2._bp`）；alpha 取值只有 0（82 处）和 256（29 处）。另 3 处参数来自变量。
- `90:38` 共 149 处，立即数 `propId` 分布：0（位置）62、0x60 的 18、0x42 的 10 等；**没有一处用立即数把 `propId=1`（混合模式）或 `propId=2`（alpha）设成常量**。
- 引擎内部（`ac2_ML.c`）直接调用混合调度器的位置里，模式是常量的有：`0x80`（9 处，用途未逐处核对）、`5`+`0x100`（3 处，向黑渐变整屏）、`7`+`0x100`（1 处）、`1`+`0x100−变量`（1 处）；绘制对象时的模式取自对象字段（`FUN_00421250`）；过渡路径用 `0x20/0x21`（`60286` 行附近）、`0x80/0xC0/0xC1`（`55056` 行附近）。
- 故事脚本（`_bs`）里画图的混合模式是由系统脚本在运行时通过变量传下来的，静态看不到具体值。所以：**模式 1、0x80、0x20/0x21、5、0xC0/0xC1 是确定会用到的；2、3、4、6、7、8、9、0x40、0x41、0xF0、0xFF 在系统脚本里没有静态证据**，可能只在故事脚本的特效（如闪光、阴影）里偶尔用到，优先级可以放低。

## 选项 `DAT_00534688`（0x1220000）

- 唯一的写入点是 `FUN_00408c00`，只被脚本子 opcode **`91:0A`**（处理器 `0048F7C0`，`SetEngineOption(key, value)` 形的接口，`key=0x1220000` 时写它）调用。
- 它位于 `.data` 节的 BSS 部分（`.data` 的虚拟大小 `0x69324` 大于文件中大小 `0x3400`，地址 `0x534688` 超出文件内容），**默认值是 0**。
- `91:0A` 在 114 个 `_bp` 里**没有任何静态调用点**，所以实际一直是 0：模式 2 的加法永远走“按源 alpha 加权”的路径（`f=((sa>>1)·P)>>8`、`out=min(255,d+s·f/128)`），`==1` 的分支可以不实现。

## SIMD 路径与标量路径的舍入差（`scripts/blend_rounding.py`，静态模型）

每行末尾的奇数个像素（或不足一对的）走标量尾部，其余成对走 SIMD，所以同一张图里两种路径会混用：
- 模式 0/1 的 BGRA→BGRA（`40c480`/`40cda0`）：标量用整数 `div`，SIMD 用 `rcpps`（12 位精度）。`a_o` 在 SIMD 里是精确的（单精度能精确表示），只有倒数有误差。按 `rcpps` 相对误差 ≤ 1.5·2⁻¹² 建模，权重 `ws/wd` 最多差 **1**，约 9.5% 的 `(sa, da)` 组合会出现 1 的差，颜色最多差 1。
- 模式 7 的 BGRA→8 位（`00418770`）：标量 `d·(0xFF00−sa·P)>>16`，SIMD `d·(256−(sa·P>>8))>>8`，在全部 `(P, sa, d)` 里 66% 的输入结果不同，**最多差 2**。这个路径使用频率很低（8 位目标几乎不出现）。
- 其它读过的内核（主合成 `0040ca80`、模式 2/4/5/6 的 2→1）标量尾部与 SIMD 用同一张表，公式一致，不存在这类差异。
- 这里是静态建模；用 Unicorn 跑真实内核的实测值见下一节（模式 0/1 的 2→2 最大差 3，模式 7 的 2→3 最大差 2，与此处建模一致或略大）。

## 对 OpenBGI 的含义

- 大多数“特效”模式其实是标准 Photoshop 混合：Multiply(4)、Screen(6)、Overlay(8)、Hard Light(9)、Add(2)、Subtract(3)，再加 Over(1) 与 Copy(0)。可以用整数运算逐像素写一个参考实现（本文公式），再用 SDL3/SIMD 优化。
- 要得到**逐位一致**的结果，需用同样的取整：`>>8`/`>>7`、`pmulhw` 的 `(a·b)>>16`、饱和加减；SIMD 的 `rcpps` 近似使模式 1 在 SIMD 与标量路径间有 ±1 差（见“舍入差”一节），原版显示结果取决于像素是否落在 2 像素对内，这点不必逐位复刻。
- `P` 的约定因模式而异（见上表）；调度前必须由 `CDspObj` 的 `FUN_004213c0` 换算。换算见“CDspObj 到 P 的换算”。

## 动态验证（Unicorn 跑真实内核，`scripts/emu.py` + `scripts/verify_blend.py`）

环境：`analysis\.venv`（uv 创建，`unicorn 2.1.4`、`capstone`、`numpy`）。做法：把 `ac2_ML.exe` 的各节按原地址映射进 Unicorn（Haswell 型号，开 SSE），补上两张运行时初始化的表（`0x5346b0`：257 项、`0x5356d0`：129 项，第 i 项八个字全是 i），把安全 cookie 检查 `0x4cf4f7` 改成 `ret`，然后用 `fastcall`（`ecx=目标位图, edx=源位图`，参数在栈上）直接调用各模式的入口，位图结构为 `+0 数据, +4 行距, +8 宽, +0xC 高, +0x10 格式, +0x14 每像素字节`。随机像素、宽度取 1/2/3/8/9（宽 1 只走标量尾部，偶数宽只走 SIMD 成对路径），与本文参考公式逐像素比较。运行：

```
.venv\Scripts\python.exe scriptserify_blend.py        # 全部
.venv\Scripts\python.exe scriptserify_blend.py -v c940  # 只跑名字含 c940 的并显示最差样例
```

**结果：40 个“模式 × 格式组合”里 35 个与参考公式逐位一致**（含全部 16 位、8 位路径、模式 0x40/0x80/0xC1/0xF0/0xFF 以及模式 2/3/4/5/6/8/9 的所有 32 位组合、`0040c940`、`0040f040`）。其余 5 个只在 SIMD 成对路径上有小偏差，标量路径逐位一致：

| 组合 | SIMD 与标量最大差 | 原因 |
|---|---|---|
| 模式 0/1 的 2→2（`40c480`/`40cda0`） | 3 | `rcpps` 近似倒数；另外**成对处理时 `sa=0` 的那个像素也会被改写**（颜色被轻微改动，若目标 alpha 也是 0 则颜色变 0，但 alpha 为 0 的像素不可见） |
| 模式 0 的 2→1（`40c300`） | 2 | SIMD 没有 `sa==255` 直接覆盖的特例 |
| 模式 2 的 2→2（`40e280`） | 1 | 取整 |
| 模式 7 的 2→2（`4184b0/418620`） | 1 | 同 8 位版的常数差 |
| 模式 7 的 2→3（`418770/4188b0`） | 2 | 标量用 `0xFF00`，SIMD 用 `256` |

验证中发现并已更正的错误（静态阅读读错或漏读的）：
1. **模式 0/1 的 2→2，目标 alpha 并不是 `floor(a_o)`**：内核把 `a_o` 与颜色混合时顺带算出的 alpha 通道结果相**或**：`A_out = (a_o_int) |floor(a_o) | min(255, (sa·ws + da·wd) >> 8)`。目标 alpha 为 255 的常见情形几乎不受影响，但往透明图层上叠半透明像素时 alpha 会偏大。参考实现要照这个公式做。整数模型：`Q=256−P`（模式 0 取 256），`e=sa·Q`，`c=(da·(0x10000−e))>>8`，`den=e+c`，`ws=(e<<8)/den`，`wd=(c<<8)/den`，颜色 `(d·wd+s·ws)>>8`。
2. **模式 2 的 2→2，目标 alpha 的加法用的是 `s_a·(P>>1)>>7`**（不是 `f`）：`A_out=min(255, d_a + ((s_a·(P>>1))>>7))`；颜色仍用 `f=((sa>>1)·P)>>8`。
3. **`0040c940`（模式 1 的 1→2）的颜色用 16.16 定点**：`e=255·(256−P)`，`c=(da·(0x10000−e))>>8`，`den=e+c`，`ws=(e<<16)/den`，`wd=(c<<16)/den`，颜色 `(s·ws+d·wd)>>16`，目标 alpha `den>>8`，没有第 1 条的“或”。
4. **模式 0 的 2→1 不是预乘**（上表已更正）。预乘到黑底的是模式 0x80 的 2→1（`0040c140`），那条验证通过。
5. 目标为**无 alpha 的 32 位图（格式 1）时，第 4 字节是垃圾值**，内核可能改写它；重写时当作不关心的字节。

## 已验证 / 静态推断 / 未知与风险

已验证：上面“动态验证”表中的全部组合（内核在 Unicorn 里的真实输出）；`CDspObj` 到 `P` 的换算和脚本里的模式分布仍是静态读代码的结果。未验证的有：(a) 调度器 `FUN_0040b9d0` 已验证（见上节），只剩 `flag≠0` 的多线程分块路径没跑；(b) 位图格式 4–7（表里有 `{6,4}` 字节的格式）没覆盖；(c) 模式 4/7 等在 `P=0x100` 之外边界的少量分支。
静态推断：`CDspObj` 到 `P` 的换算、脚本模式统计、`DAT_00534688` 默认 0。
未知与风险：故事脚本（`_bs`）里运行时传入的混合模式没法静态统计；`90:38 propId=0xFFFF` 在故事脚本里是否会清 `+0x114` 位 0 没统计；Unicorn 的 `rcpps` 不一定与真机逐位相同（Intel/AMD 本来也不同），SIMD 成对路径的偏差上界 3 是在 Unicorn 上量的，真机上可能略有不同。
