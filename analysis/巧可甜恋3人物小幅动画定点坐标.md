# 巧可甜恋3：人物小幅动作丢失小数（2026-11-09）

## 复现与证据

第一个普通存档读档后推进一句，人物 `80000004` 换表情后执行两段 `90:29` 动作，每段 200 ms，curve=2，fps=250：

- 第一段从 `(360,0,0)` 经过 `(360,2,0)` 到 `(360,5,0)`。
- 第二段从 `(360,5,0)` 经过 `(360,2,0)` 回到 `(360,0,0)`。

路径内存的坐标是 16.16 定点数。旧代码在 `advance_motions()` 中先将插值结果转换为整数像素，再写到 Sprite；`90:5C`、`91:33` 也直接右移丢弃小数。绘制侧再按整数位置合成。因此短小动作只剩几次整像素跳变，负数位置的截断还可能改变落点。

这与此前 `90:19` 的表情交叉渐变错误不同；原存档与之前诊断的存档 SHA-256 一致。

用原版第三作 EXE 的样条构造 `0x494650`、求值 `0x4945B0` 直接计算同一路径（Unicorn，无窗口）：

| 时间 | 原版 Y（16.16 原始值） | 像素 | 旧程序 |
| --- | ---: | ---: | ---: |
| 16 ms | 29003 | 0.44255066 | 0 |
| 32 ms | 59058 | 0.90115356 | 0 |
| 48 ms | 90975 | 1.38816833 | 1 |
| 128 ms | 261855 | 3.99559021 | 3 |
| 192 ms | 326835 | 4.98710632 | 4 |

原版求值是在 16.16 原始整数上保留小数后再输出整数；样条形状和 easing 本身在这段动作中没有偏差。探针只替换依赖 Windows CRT 调度的 floor 为等价 x87 floor，保留原版样条运算；EXE 身份复用 `probe_ac3_crossfade.py` 的 SHA-256 校验。

## 修复

- Sprite 保存坐标的小数部分；`90:29` 起点、插值结果、零时长终点，`90:5C`、`91:33` 和 `91:38` 的固定坐标读写保留完整 16.16 值。整数 move 清除旧的小数。
- 投影合成在应用透视缩放、原点及固定偏移之后才分离整像素与小数。旋转投影分支也保留位置小数。
- 已有 GPU blit 增加亚像素平移采样，保持原版 SampleXY 的七位小数插值，补齐边缘采样和屏幕裁剪；整数位置沿用原路径，smooth 关闭时沿用整数采样。移动本身不增加逐帧 CPU 回读、变换和上传。
- `OBGI_TRACE_SCENE` 增加 `PROJECT` 行，记录完整定点坐标、小数部分及 smooth 状态。
