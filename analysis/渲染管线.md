# 渲染管线：软件合成 + D3D9 呈现层（任务 F，Claude 研究）

依据 `out/ac2_ML.c`；工具 `scripts/extract_shader.py`（读 exe 资源）、`out/res_SHADER.asm.txt`（用 `d3dcompiler_47.dll` 的 `D3DDisassemble` 反汇编所得）。除标注外均为【静态推断】。

## 核心结论

**画面合成全部在 CPU 上做，D3D9 只负责把最终帧贴到屏幕。**

- 整个 EXE 里对 D3D9 设备（全局 `DAT_005461a0`）的调用点只有约 60 处，集中在 0x0046c0e0–0x0046d1xx 的“设备创建/重置/呈现”函数，没有任何绘制精灵、设置多纹理混合、顶点缓冲的游戏逻辑代码。
- 精灵/背景/立绘/特效叠加、alpha 与各种混合模式、文字、遮罩渐变（wipe）都发生在**位图（图像槽）层**：CPU 位图混合调度函数 FUN_0040b9d0（经 FUN_0040b410 的“按位置+混合模式+alpha 拷贝”入口）。
- 每帧：CPU 合成出一张最终位图 → 上传为 D3D 纹理（`DAT_005461ac`）→ 画一个全屏四边形（`DrawPrimitiveUP`，4 个顶点，FVF 0x144）。
- OpenBGI 含义：**不需要 GPU 精灵管线**。用 SDL3 的一个纹理（或 SDL_GPU 一个全屏三角）呈现软件帧缓冲即可；混合运算需要自己写（SIMD 可选）。这极大简化了渲染部分，但**要把 CPU 混合公式逐种还原**（见下）。

## D3D9 设备创建（FUN_0046c0e0，120299 行附近）

- `Direct3DCreate9(0x20)`（SDK 版本 32）。
- `D3DPRESENT_PARAMETERS`（0x38 字节，起于 `DAT_005461b8`）：
  - BackBufferWidth/Height = 游戏分辨率（`DAT_00545c9c/ca0`；全屏时会按桌面改，窗口模式为 0 表示用窗口客户区）
  - BackBufferFormat = `DAT_00545ca8`（窗口模式 0 = UNKNOWN）
  - BackBufferCount = 1
  - SwapEffect = 窗口 3（COPY），全屏 1（DISCARD）
  - EnableAutoDepthStencil = 0（但 AutoDepthStencilFormat 填了 0x50=D16，未使用）
  - Flags = 全屏时 LOCKABLE_BACKBUFFER，窗口 0
  - FullScreen_RefreshRateInHz = `DAT_00545ca4`（窗口为 0）
  - PresentationInterval = `0x80000000`(IMMEDIATE) 或 0(DEFAULT，垂直同步) 由 FUN_0046c490 决定
- `CreateDevice(adapter, HAL(1), hwnd, 0x44|0x24 回退)`：先试硬件顶点处理 + FPU_PRESERVE，失败改软件顶点处理。
- 初始渲染状态：CULLMODE=NONE(1)、ZENABLE=0、LIGHTING=0、ALPHABLEND=1；采样器 0 的 ADDRESSU/V=BORDER(4)、边框色=0（透明黑）。
- 设备丢失处理：`TestCooperativeLevel`（FUN_0046c340），DEVICENOTRESET 时释放纹理/着色器后 `Reset`，重建后用 `FUN_0046d260` 重新选择呈现模式。

## 呈现（FUN_0046c4xx，约 119855–120130 行）

固定的每帧流程：Clear → BeginScene → 设置采样/混合 → SetTexture → SetFVF → DrawPrimitiveUP（单个四边形，顶点数据来自表 `DAT_00546118` 的 28 个 float，再加偏移）→ EndScene → Present（脏矩形版本 Present 带 RECT 列表）。

**呈现模式**（`DAT_00546100`，FUN_0046d260 设置）：

| 值 | 含义（推断） |
|---|---|
| 0 | 固定管线，点采样（或配置的过滤） |
| 1 | **像素着色器**缩放（见下） |
| 2 | 固定管线，线性 |
| 3 | 窗口→线性(2)，全屏→点采样(0) |
| 4 | 窗口→线性(2)，全屏→着色器(1) |

固定管线路径的纹理级别状态：COLOROP=MODULATE(4)，COLORARG1=TEXTURE，COLORARG2=DIFFUSE，ALPHAOP=SELECTARG1(2)，ALPHAARG1=TEXTURE；混合状态：BLENDOP=ADD(1)，SRCBLEND=ONE(2)，DESTBLEND=ZERO(1)——即不混合，直接覆盖；颜色顶点为白色，所以等价于“拷贝纹理”。

## 内置像素着色器（RT `SHADER` id 0x81，DSC 压缩，解后 4208 字节）

【已验证】从 exe 资源取出并用 D3DDisassemble 反汇编（`out/res_SHADER.asm.txt`）：`ps_2_x`，由 HLSL 9.29 编译；常量表：`g_f2SizeOfSourceTexture01`(c0)、`g_f2AvailableAreaOfSourceTexture01`(c1)、`SourceSampler01`(s0)。
【推断】功能是 **16 点双三次（bicubic）放大**：权重函数为 Catmull-Rom 型三次多项式（|x|<1：`1.5|x|³−2.5x²+1`；1≤|x|<2：`−0.5|x|³+2.5x²−4|x|+2`，代码里放大 2 倍表示成 `4−8|x|+5x²−|x|³` 等），16 次 `texld`，对超出“有效区域”(c1) 的采样点权重置 0（避免读到纹理填充区的黑边）。用于全屏/高质量缩放（需要 PS 3.0 能力，`FUN_0046d150` 检查 `DAT_00545c98 >= 0xffff0300`）。
OpenBGI：直接按此公式写一个 bicubic 缩放（SDL_GPU 片元着色器或 CPU），其余模式用 SDL 的线性/最近邻过滤。

## CPU 合成：混合模式调度（FUN_0040b9d0）

输入：目标位图、源位图、模式 `mode`（0–0xFF）、alpha（0..0x100）；`FUN_0040b980` 检查像素格式兼容，alpha>0x100 返回错误 3。位图格式字段 `[4]`：0 = 16 位、1 = 32 位 BGRX、2 = 32 位 BGRA、3 = 8 位（详见 `混合公式.md`）。每个模式函数再按（源格式, 目标格式）分发到具体内核（SSE 向量化，整行处理；大图通过 FUN_0041f760 分块**多线程**并行）。

| mode | 函数 | 推断 |
|---|---|---|
| 0 | FUN_0040c240 | 直接拷贝（按格式组合） |
| 1 | FUN_0040c6c0 | 常规 alpha 混合（alpha=0 退化成拷贝；0x100 完全覆盖） |
| 0x20 | 同 mode 1 | 同上（别名） |
| 2 | FUN_0040dce0 | 另一种 alpha 混合（疑为使用源 alpha 通道的“带通道混合”） |
| 0x21 | 同 mode 2，alpha 取 `0x100−alpha` | 反向 alpha |
| 3 / 0x22 | FUN_0040e560 | 加法/变亮类（`0x22` = `0x100−alpha`） |
| 4 / 0x23 | FUN_0040e760 | 减法/乘法类 |
| 5 / 0xC0 | FUN_0040ed50 | 同类混合 |
| 6–9 / 0x24–0x27 | FUN_00416e40 / 00418260 / 00417200 / 00417810 | 其余变亮/变暗/叠加类（0x24–0x27 为反向 alpha） |
| 0x40 | FUN_0040f170 | 带遮罩/参数的混合 |
| 0x41 | FUN_0040b940 | 特殊（无 alpha 参数） |
| 0x80 | FUN_0040c040 | 对灰度/遮罩的拷贝 |
| 0xC1 | FUN_00411e40(…, 0xffffff, alpha) | 以白色为目标的混合（遮罩着色？） |
| 0xF0 | FUN_0040d000 | 特殊 |
| 0xFF | FUN_00412560 | 特殊（含 alpha 通道的覆盖？） |

**尚未解出每个模式的像素公式**：内核是 SSE 向量实现，Ghidra 反编译难以阅读。可行方法：①直接读这些内核的汇编；②在 Wine 下运行原版，对已知输入位图做“差分测试”，用 `90:18` 图像复制的各混合模式（`bitmap*.bp` 里的脚本直接可调）还原公式；这是后续最需要的实验。

## 窗口与分辨率

字符串 `Buriko General Interpreter for AmairoChocolate2ML is executing.`；窗口/全屏切换通过 Reset；`FUN_0046b2f0` 取桌面分辨率；游戏本身的虚拟分辨率由图像槽决定（背景 1280×720 的 CG；`.bm` 1320×760 特效为过扫描）。呈现时按窗口客户区缩放（不保持比例的行为未查）。

## 已验证 / 静态推断 / 未知与风险

已验证：SHADER 资源的反汇编结果；D3D9 设备调用点只集中在呈现函数（以调用计数核对）。
静态推断：CPU 合成架构、模式表含义、呈现模式 0–4、D3DPRESENT_PARAMETERS 字段映射。
未知与风险：每个混合模式的像素公式；呈现模式 0/2 的过滤差异、黑边/缩放比例逻辑；颜色空间/gamma；多线程合成的分块对结果无影响（只影响速度）。
