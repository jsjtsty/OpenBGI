# OpenBGI 引擎设计

本文是正式实现的指导文档，于 2026-10-28 定稿初版。逆向资料（格式、VM、子 opcode 表）见同目录下的其他文档；本文只讲新引擎怎么设计。

## 0. 已定决策

| 项 | 决定 |
|---|---|
| 语言与构建 | C++23（不用模块），CMake Presets，vcpkg 清单模式 |
| 平台层 | SDL3 全家桶：SDL3、SDL_GPU，SDL3_ttf 只取其依赖 FreeType 和 HarfBuzz |
| 视频 | FFmpeg（`.mpg`）；`.bm` 自研解码器 |
| 文字 | FreeType 光栅化，HarfBuzz 塑形，排版逻辑自研 |
| 音频解码 | libvorbis 或 stb_vorbis，混音器自研 |
| 总原则 | **行为大致一致，内部实现最优化**。不逐函数移植原版 exe，渲染和架构重新设计 |
| 存档 | 自有格式，带版本号；以后再加原版 `.sud` 导入功能 |
| 目标平台 | 桌面端（Windows、Linux、macOS）加移动端，暂不含网页 |
| 最低硬件 | 支持 Vulkan、D3D12 或 Metal 的设备 |

若以后要支持网页，只需替换 `render/` 后端，其余层不受影响。

## 1. 兼容边界

| 层 | 要求 | 内容 |
|---|---|---|
| 脚本可观察 | **完全一致** | 见下方列表 |
| 数据解码 | **无损一致** | arc、DSC、CBG、BM、BW、GDB、SDC 的解码结果 |
| 呈现 | **视觉一致** | 合成方式、缩放、字形光栅化、混音、视频色彩转换 |

"脚本可观察"指以下内容：
- VM 语义；
- 每个子 opcode 的参数、返回值和副作用；
- 线程调度顺序；
- 毫秒时钟；
- 文本换行与分页位置；
- 命中测试结果；
- 图片尺寸等查询结果。

判断规则：只要某个结果会被压回 VM 栈、写入脚本内存，或者影响调度，它就属于第一层。

## 2. 总体结构

```text
src/
  core/      句柄、日志、时钟、任务池、错误类型（std::expected）
  vfs/       arc 挂载、内存映射、覆盖目录、路径规范化
  formats/   DSC CBG BM BW GDB SDC：纯函数，零平台依赖
  vm/        解释器、线程、调度器、地址空间、子 opcode 注册表
  bindings/  子 opcode 适配层，按 80/81/90/91/92/A0/B0/C0 分文件
  services/  graphics text sound movie save input system
  render/    SDL_GPU 后端、着色器、纹理与字形图集、过渡效果
  audio/     混音器、Vorbis 流、BW 循环逻辑
  app/       主循环、启动、调试面板（Dear ImGui）
tests/  tools/  shaders/
```

依赖方向自上而下：
- `formats` 只依赖 `core`。
- `vm` 不依赖任何服务。
- `bindings` 是唯一同时认识 VM 和服务的层。
- `render` 和 `audio` 只被服务调用。

## 3. VM

- **解释器。** 主 opcode 用分发表，热路径不做虚函数调用。
- **子 opcode 注册表。** 每项登记 `{id, 名称, 弹栈数, 压栈数, 处理函数}`，运行时校验栈的增减与登记值一致。
  - **未实现的子 opcode 直接报错**，禁止自动补零。
  - 实现进度可以从注册表直接统计，按 `out/subop_tiers.tsv` 的 A1、A2、B、C 分档推进。
- **地址空间。** 地址高 6 位是标签：1 表示线程程序，2 表示线程数据栈，0 表示全局内存。每种标签对应一个独立的段，带边界检查，越界即断言。
- **脚本线程。** 只是一个显式状态结构，包含 program、locals、expr 栈、ip、调用栈、等待对象和消息队列，**不对应操作系统线程**。
- **调度器。** 规则与原版 `FUN_0049be00` 一致：
  - 按创建顺序遍历线程，本帧新建的线程追加到队尾并在当帧运行；
  - 带等待对象的线程，要等等待对象报告就绪才运行；
  - 返回码 1 和 5 转下一个线程；2 留在当前线程；3 切换到指定线程；4 结束当前线程；6 转下一个线程并跳过本帧剩余线程。
  - 线程表为空时，重新初始化各子系统，并重建入口线程（autoload）。
- **资源 ID。** 脚本可见的资源 ID 一律用带代数（generation）的整数句柄，失效句柄可以被检测出来。

## 4. 子 opcode 适配层与服务

```text
解释器 ──► bindings（弹参数 → 调服务 → 压返回值） ──► services
```

- **binding 只做三件事**：参数转换、调用服务、写回结果。不含业务逻辑。
- **services 是普通 C++ 接口**，可以脱离 VM 单元测试：
  - Graphics：场景对象、图层、过渡；
  - Text：消息窗口、排版、注音；
  - Sound：声道、BGM、语音、音效；
  - Movie：BM 与 mpg 播放；
  - Save：存档与读档；
  - Input：输入与消息队列（对应 `sysmsg` 线程的 `80:A0` 等）；
  - System：时钟、配置、窗口。
- **所有服务都必须能序列化**，从第一天起就这样做。存档 = VM 状态 + 各服务状态（见第 10 节）。

## 5. 渲染

**保留模式场景。** 子 opcode 只修改纯数据的场景描述，渲染器每帧读取它的快照，用 SDL_GPU 提交。VM 永远不直接访问 GPU。

场景描述包括：
- 图层树；
- 每个对象的纹理句柄、位置、缩放、透明度、混合模式、裁剪和过渡参数。

**混合模式：**
- alpha、加算、乘算、屏幕等常见模式，用 GPU 的固定混合状态。
- 需要读取目标像素的特殊模式，先把下层渲染到中间纹理，再用着色器合成。
- 已验证的 35 个 CPU 混合内核不进入运行时，改作着色器的参考实现，允许 1 到 2 级的误差。

**颜色约定：**
- 全部使用预乘 alpha。
- **在 gamma 空间混合**，不用 sRGB 帧缓冲。原版就是在 gamma 空间混合的，改成线性空间会让半透明观感偏离原版。

**分辨率：**
- 脚本在逻辑坐标（1280×720）里工作。
- 渲染目标使用窗口的真实分辨率；图片用高质量滤波缩放。
- 文字按实际像素尺寸光栅化，高 DPI 屏上会更清晰。

**过渡效果。** 遮罩擦除、淡入淡出等都写成着色器。截取当前画面改为渲染到纹理。

GPU 化之后，以下功能仍需要 CPU 端数据：

| 需求 | 方案 |
|---|---|
| 按 alpha 判定按钮命中 | 解码时保留 CPU 端的 alpha 或命中掩码 |
| 存档缩略图 | GPU 异步回读，只在存档时触发 |
| 脚本查询图片尺寸或像素 | 走 CPU 端元数据，不访问 GPU |

## 6. 时间模型

- **VM 按固定逻辑节拍运行。** 节拍间隔由 `90:02` 设定（1000/fps），脚本看到的时序与原版一致。
- **引擎自管的动画在渲染时按连续时间插值**，例如 `B0:05` 那类定时过渡、淡入淡出和移动。高刷新率屏幕上过渡更平滑，且不影响脚本逻辑。
- **时钟可注入。** 无头模式使用虚拟时钟加输入回放，整个运行完全确定，用于回归测试和调用序列对比。

## 7. 并发

| 线程 | 职责 |
|---|---|
| 主线程 | SDL 事件、按逻辑节拍跑 VM、生成场景快照、提交渲染 |
| 工作线程池 | DSC、CBG、BM 解码，字形光栅化；结果以句柄形式异步就绪 |
| 音频回调线程 | 自研混音器挂在 SDL_AudioStream 上 |
| 视频线程 | FFmpeg 解码；YUV 平面直接上传，着色器转换颜色；可选硬件解码 |

线程之间只通过命令队列和不可变快照通信，避免互斥锁扩散。

如果脚本要求同步拿到资源（例如查询尺寸），只读取头部元数据，不等待完整解码。

**后期优化。** 静态扫描接下来的 `_bs` 脚本，预读即将用到的图片和语音。

## 8. 音频

- 自研混音器，支持多声道、音量和淡入淡出。
- 实现 `BW格式.md` 中的循环规则：
  - 循环标志和循环起点取自文件头；
  - `A0:12` 可以覆盖：文件名相同时，从头循环整个文件；文件名不同时，使用"前奏 + 循环"双文件模式。
- 循环点精确到采样，前奏与循环之间无缝衔接。

## 9. 文字

- 排版逻辑（控制码、注音、换行）沿用已验证的模型，**换行和分页位置必须与原版一致**。
- 字形用 FreeType 光栅化，按实际像素尺寸生成，存入字形图集缓存。
- 用 HarfBuzz 塑形；竖排时启用 `vert` 和 `vrt2` 特性，替换竖排标点。
- 字体随包固定，不依赖系统字体。
- 不使用 SDL3_ttf 的高层文本 API，因为它无法表达 BGI 的注音和控制码。

## 10. 存档

- 自有二进制格式。文件头包含：魔数、格式版本、引擎版本、游戏标识。
- 正文按块组织，每块是 `{块类型, 块版本, 长度, 数据}`，结构如下：

```text
Header
Chunk VM       全局内存、各线程状态
Chunk GFX      场景状态（只存逻辑状态，不存纹理像素）
Chunk SND      各声道的文件、位置、循环参数、音量
Chunk TEXT     消息窗口与回想记录
Chunk THUMB    缩略图
Chunk META     时间、章节、游玩时长
```

- 读档遇到未知块就跳过。每个块各自负责从旧版本升级。
- 系统数据（已读标记、设置、CG 回想）与存档槽位分开保存。
- 以后增加 `.sud` 导入器，把原版存档转换成上面的块。它是一个独立工具，不让原版的内存布局渗入新架构。

## 11. 文件系统

- 挂载 arc 时使用内存映射，不做拷贝。
- 文件名不区分大小写，路径统一规范化。
- 覆盖目录优先于 arc，用于汉化、模组和资源替换。
- 文件读写都经过 vfs，引擎内不直接操作原始路径。

## 12. 验证策略

| 对象 | 方法 | 标准 |
|---|---|---|
| formats | 用 Python 和 Unicorn 导出的测试向量比对 | 逐字节一致 |
| VM 与 bindings | 原版 exe 进程内钩子（只读日志，不改游戏目录）录下子 opcode 的调用序列、参数和返回值，与无头模式逐条对比 | 第一个分歧点就是下一个 bug |
| 混合与着色器 | 与已验证的 CPU 内核比较 | 误差不超过 2 级 |
| 画面 | 与原版截图做 SSIM 或容差比较 | 视觉一致 |
| 音频循环 | 检查采样位置 | 精确 |

Python 原型（`scripts/`）不再扩展，只作为对照基准和一次性工具保留。

## 13. 工程规范

- 代码检查：clang-format、clang-tidy；Debug 配置开启 ASan 和 UBSan。
- 测试框架：doctest。
- 性能分析：Tracy。
- 调试面板：Dear ImGui，可查看 VM 线程、图层树、声道和资源缓存。
- 持续集成：GitHub Actions，覆盖 Windows、Linux 和 macOS。
- 错误处理：用 `std::expected`，热路径不抛异常；资源用 RAII 管理。
- 不使用全局单例，只有一个 Engine 上下文，显式传递。

## 14. 实现顺序

1. 搭工程骨架：`core`、`vfs`、`formats`，用测试向量验证。
2. 无头模式下的 VM、调度器和子 opcode 注册表。实现启动路径上的子 opcode，用原版钩子对比，目标是跑到标题画面。
3. 场景服务和 SDL_GPU 渲染器，让标题画面显示出来。
4. 文字和消息窗口，跑到第一句台词。
5. 音频、选项和存读档。
6. 视频（BM、mpg）、调试面板完善、预读优化。
7. 原版 `.sud` 存档导入。
