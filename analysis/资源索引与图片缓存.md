# 资源索引与图片缓存

2026-11-08。针对《巧可甜恋3》设置菜单返回时，脚本一帧检查约 1 万个存档文件并重复加载标题图片的卡顿。

## 目录负查询索引

`DirectoryIndex` 为 `80:34` 检查游戏目录绝对路径时建立单帧目录快照。按父目录枚举文件名，不存在的 ASCII 文件名可在内存中判定；存在的候选仍用文件系统确认普通文件类型，因此移除文件或更改文件类型不会因正结果缓存而隐藏。非 ASCII 路径及目录中有非 ASCII 文件名时，无法可靠模拟跨平台大小写与 Unicode 规则，回退文件系统查询；Unix 文件名包含反斜线的特殊情况也保留正确性。扫描失败、目录超过 16384 条或单帧目录数超过 64 时回退正常查询，不把失败视为文件不存在。

每个 VM 帧更换快照；本引擎写入、删除、创建目录等操作立即清空快照。外部程序同一帧创建的文件可能直到下一帧才可见；正候选每次仍实时检查。索引只加速目录枚举，不持久缓存路径是否存在，不改变归档成员查找结果。路径类型复杂、Unicode 名称、带异常或缺失的目录可能不走加速路径。

## 归档图片缓存

`ArcImageSource` 以 `(归档前缀, 成员名)` 为键，在会话内缓存归档图片的已解码像素及尺寸、格式、基准信息；容量默认 128 MiB，按最近使用顺序淘汰。超过容量的单张图片不缓存，失败结果不缓存。每次命中前仍查询松散文件：资源目录或新加搜索路径有同名文件时优先读取，并且松散文件从不缓存，因此修改或删除后立即生效。读取 API 返回来源类型，避免将实际读到的松散文件误存为归档图片。

缓存是 CPU 像素缓存，命中时仍复制和上传 GPU；没有引入异步加载。归档沿用现有会话内映射语义：运行中替换整个归档文件不保证实时生效，重启会话可重新加载。

## 测量与验证

在同一机器 Debug 构建、固定 1600 帧及模拟设置菜单点击/返回的无窗口运行中，设置返回涉及的两个脚本帧，基线分别约 2842/1737 ms，索引与缓存后约 435/376 ms。Release 构建同路径约 81/65 ms。单次测量，受系统负载、文件缓存及渲染模式影响；这些数字不等同于窗口交互的端到端延迟。首次图片加载仍需要解码，画面合成及 GPU 上传开销也仍存在。

相关测试覆盖单帧写入与删除使索引失效、跨帧刷新、松散文件覆盖、缓存淘汰和容量。两作固定帧标题截图分别与优化前 PNG 的 SHA-256 完全一致；这只验证对应场景，不代表全游戏渲染已验证。
